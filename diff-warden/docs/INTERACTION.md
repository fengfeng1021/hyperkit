# Diff Warden - 互動規格

> 寫在任何一行 CSS 之前。這份文件決定畫面上有什麼、每個東西有幾種狀態、
> 失敗的時候說什麼話、以及為什麼使用者下週會再打開它。
> 視覺 token 在 `docs/DESIGN-DIRECTION.md` 與 `css/tokens.css`。

**閱讀提醒**：下方版面草圖裡的 `↳` `▸` `‹` `◉` `◎` 是文字稿的速記符號，**不是實作規格**。
實作時一律換成 SVG sprite 裡的 symbol（`i-leader` `i-chevron` `i-strike`），
Unicode 字元不得當圖示使用。對照表在 `docs/DESIGN-DIRECTION.md` §5「圖示系統」。

## 0. 資訊架構

### 0.1 兩種畫面，不是兩個頁面

同一個 `index.html`，`<body>` 上掛 `data-stage`：

| `data-stage` | 什麼時候 | 畫面 |
|---|---|---|
| `bed` | 首次到訪，或本機沒有任何試件記錄 | 空試件台 + 下方三段短說明 |
| `deck` | 已選資料夾、載入範例、或回訪且授權仍有效 | 三欄工作台，不可捲動（內部各自捲動） |

**回訪的人不會看到 `bed`。** 開啟頁面時 `boot()` 先查 IndexedDB：
有 `specimen` 記錄且 `handle.queryPermission({mode:'read'})` 回 `granted` 就直接進 `deck`。
回 `prompt` 就進 `deck` 但試件面板顯示「需要重新授權」與一個按鈕（使用者手勢才能呼叫 `requestPermission`）。
這一步是留存機制的第一格：**第二次打開時，畫面已經是工作台了。**

1. **資料流向**（水平流程列，1px 引線串接四個節點）

2. **對照表**（兩欄三列表格，見 `PRODUCT.md` §5.4）

3. **瀏覽器支援矩陣**（三列橫向清單，非表格）
   Chrome / Edge / Opera：完整，授權可續用。
   Firefox / Safari：可用，走 `webkitdirectory` 單次選取，每次要重選資料夾。
   說清楚少了什麼，不寫「不支援」。

## 1. 核心迴圈

### 進站看到什麼

**第一次**：一張空的試件台，四角有角標，中間一句話告訴你這台儀器要你放什麼上去。
**第二次以後**：工作台，你的資料夾名字已經在左上角，基準線時間在它下面，
判讀規則 16 條在右軌，狀態列讀著 `本機資產 基準線 1 判讀規則 16 歷史 5`。
**你不用重新設定任何東西。**

### 第一個動作

第一次：`選擇資料夾`（或 `看範例報告`）。
第二次以後：`掃描變動`。這是一顆按鈕、一次點擊，因為基準線已經在那裡了。

### 得到什麼

90 秒內，一份 8-15 條的結構化缺陷清單，跨檔案的排在最前面，
每一條有 `檔案:行號`、嚴重度、類別、以及一段「什麼情況下會爆」。
清單頂端一行：`已依你的 16 條判讀規則自動略過 8 條`。
右上角一顆按鈕：`匯出 Markdown`。

### 為什麼下週會再打開

三個理由，強度遞增：

1. **節奏**。他每讓 agent 產一批程式碼就該掃一次。實務上每天到每週數次。
   agent 產碼量還在放大，這是結構性成長，不是穩態需求。
2. **省事**。第二次不用選資料夾、不用設 key、不用調排除規則、不用調預算。一顆按鈕。
3. **資產**。他標記過的 16 條判讀規則在本機。換工具等於從頭調教一次。
   而且他**看得到**這件事：審查歷史刻度尺上，第 1 次 31 條、第 5 次 12 條，雜訊在下降。

第三點是唯一真正走不掉的理由，所以它佔了整條右軌。

## 2. 狀態機

通則（全域，不逐項重述）：

- **focus**：`outline: 2px solid var(--accent); outline-offset: 2px`。永不移除，永不用 `outline: none`。
  focus ring 顏色在所有表面上對比 ≥ 12:1。
- **active**：`transform: translateY(1px)`，`--dur-1` 110ms。實體按壓感，不用 scale。
- **disabled**：`--fg-disabled` 文字、`--rule` 邊框、`cursor: not-allowed`、`aria-disabled="true"`。
  **每個 disabled 控制項旁邊必須有一行文字說明為什麼不能按**（`--fg-3`，12px）。
  沒有理由的 disabled 是壞掉的介面。
- **loading**：沒有旋轉指示器。進度是**位置與數字**：探傷帶上的游標位置、按鈕內的計數（`審查中 3/11`）。
- 內容預設可見。CSS 裡沒有任何 `opacity: 0` 等 JS 來救。

### 2.1 `選擇資料夾`（主要按鈕，`bed` 與左軌各一顆）

| 狀態 | 表現 |
|---|---|
| idle | 酸黃綠填色，`--ink-on-accent` 深棕黑文字（對比 14.60:1），2px 圓角 |
| hover | 底色提亮一階至 `--accent-hi`，1px 內描邊出現 |
| focus | 通則 focus ring |
| active | `translateY(1px)`，底色降回 `--accent` |
| loading | 文字換成 `等待授權`，按鈕鎖住（原生檔案挑選器接管，不會超過幾秒） |
| success | 不停留在 success：直接轉場進 `deck`（見 §5.0） |
| error | 見 §4.2 / §4.3 |
| disabled | 不存在。這顆按鈕永遠可按 |

非 Chromium 時，這顆按鈕的**標籤不變**（同一意圖只有一種標籤），
但它下面的支援狀態行改成 `此瀏覽器沒有持久授權，每次都要重選資料夾`，
而且點下去走 `<input type="file" webkitdirectory>`。

### 2.2 `看範例報告`（次要按鈕）

hairline 邊框 + `--fg` 文字。hover 時邊框升為 `--rule-x`、底色升為 `--panel`。
按下去：0.4s 內進入 `deck`，`data-demo="true"`，主台頂端出現常駐 **範例帶**（見 §7.3）。
範例模式下所有互動都真的能跑（篩選、展開節錄、按「這類我不管」、匯出），
但寫入 IndexedDB 時前綴 `demo:`，離開範例模式時整批清掉，不污染真實資產。

### 2.3 試件面板（左軌第一格）

| 狀態 | 表現 |
|---|---|
| empty | 只在 `deck` 且無試件時出現（載入範例的情況）：`未架設試件` + `選擇資料夾` |
| ready | 資料夾名（`--font-mono`，中間省略保留頭尾）、`318 個檔案 / 已排除 2,104`、`更換` 連結 |
| scanning | 資料夾名下方一行 `讀取中 1,842 / 2,422`，數字是真的（`--font-mono` tabular） |
| permission-lost | 面板換成 `--fault-plate` 底、`i-warn` 圖示、`資料夾授權已失效` + `重新授權` 按鈕（見 §4.7） |
| error | 同上，文案依錯誤而定 |

### 2.4 `標記基準線` / `掃描變動`

兩顆按鈕在同一格，狀態互斥：

| 情況 | `標記基準線` | `掃描變動` |
|---|---|---|
| 尚無基準線 | 主要樣式，可按 | disabled，旁註 `尚未標記基準線` |
| 有基準線 | 次要樣式，可按（會覆蓋，按下去先展開一行確認列，不是 modal） | 主要樣式，可按 |
| 掃描中 | disabled，旁註 `掃描進行中` | 文字換 `掃描中 1,842 / 2,422`，可按 = 取消 |
| 掃描完成無變動 | 次要 | 次要 + 旁註 `基準線之後沒有檔案變動`（見 §4.11） |

`標記基準線` 的 loading 是真實進度：遞迴列出檔案 -> 逐檔 `crypto.subtle.digest('SHA-256', buf)` ->
每 50 檔更新一次計數（避免每檔 reflow）。可取消（`AbortController`），取消後保留舊基準線。

### 2.5 排除規則編輯器

chip 列 + `+` 按鈕。預設 7 條：
`node_modules/` `.git/` `dist/` `build/` `.next/` `*.min.js` `*-lock.json`

| 狀態 | 表現 |
|---|---|
| idle | chip：1px `--rule-strong` 邊框、`--fg-2` 文字、`--font-mono` 12px、2px 圓角 |
| hover | 邊框 `--rule-x`，右側出現 `×` |
| focus | chip 本身可 focus，`Backspace` / `Delete` 刪除 |
| editing | 點 `+` 或雙擊 chip 變成 inline `<input>`，`Enter` 提交、`Esc` 取消 |
| error | glob 語法無效：input 下方一行 `--fg` 文字 `這不是有效的路徑樣式，例如 dist/ 或 *.min.js`，input 邊框升為 `--fg-4` |
| empty | 全部刪光時顯示 `沒有排除規則，將讀取整個資料夾（可能很慢）` |

改動即時反映：檔案計數與「已排除 N」馬上重算，不用按儲存。

`Anthropic` / `OpenAI` 兩段。選中段：`--accent` 底 + 深棕黑字。未選：透明底 + `--fg-3`。

### 2.8 預算刻度

不是滑桿造型的裝飾，是一把**刻度尺**：一條水平軸，上面有 20k / 60k / 120k / 200k 四個刻痕與數字，
一個可拖曳的游標。`<input type="range">` 是真正的控制項（鍵盤 `←` `→` 每步 5k，`Home` / `End` 到底），
刻度尺是它的視覺呈現，兩者用同一個值。預設 60k。

拖動時**讀數窗即時重算**：估算 token、估算美金、批次數、被納入的檔案數。
讀數窗是 `--well` 底、1px inset 上緣 hairline、`--font-mono` 28px tabular 數字。

估算公式（寫死在 `js/budget.js`，UI 上 `估算方式` 可展開看到）：

```
輸入 token ≈ 檔案 UTF-8 位元組 / 3.6  +  系統提示 1,150  +  關聯圖 (檔數 × 24)
輸出 token ≈ 檔案數 × 420，上限 8,000
花費 = 輸入 × 單價in + 輸出 × 單價out
```

單價寫在 `js/pricing.js` 且**標明取得日期**，UI 上顯示 `單價依 2026-08 公告，實際以供應商帳單為準`。
不假裝這是即時報價。審查結束後用回傳的 `usage` 顯示**實際**用量與花費，並把估算落差寫出來：
`估 47.2k / 實際 44.8k，低 5%`。估準與估不準都要顯示。

### 2.9 檔案挑選表

預設收合，標頭 `檔案挑選  11 選 8  47.2k token  ▸`。展開後是一張表（不是卡片）：

| 欄 | 內容 |
|---|---|
| ☑ | checkbox，使用者可覆寫 |
| 檔案 | `--font-mono` 路徑，中間省略 |
| 變動 | `+312 / -47`（自基準線起的行數增減），`--font-mono` tabular |
| 為什麼被選 | `變動量第 1` / `新檔案` / `被 checkout.js 引用` / `超出預算，排入第 2 批` |
| token | 估算值 |

**「為什麼被選」是這一欄存在的全部理由**。挑選策略要能被看見、被反駁、被覆寫。

## 3. 鍵盤路徑

### 3.1 Tab 順序

DOM 順序即 Tab 順序，不使用正值 `tabindex`。
`deck` 的 DOM 順序：masthead -> 左軌（試件 -> 基準線 -> 排除規則 -> 掃描設定 -> 開始審查）
-> 主台（探傷帶 -> 清單工具列 -> 略過條 -> 缺陷清單）-> 右軌（規則庫 -> 歷史尺）-> 狀態列。

`< 1024px` 右軌是抽屜：開啟時 focus 移入抽屜第一個可 focus 元素，關閉時還原到觸發它的晶片。
抽屜開啟期間**不做 focus trap**（它不是 modal，使用者應該能 Tab 回主台）。

第一個可 focus 元素是 `跳到缺陷清單` 的 skip link。

### 3.2 缺陷清單的 roving tabindex

清單整體只佔一個 Tab 停留點。進入後：

| 鍵 | 動作 |
|---|---|
| `↓` / `j` | 下一條 |
| `↑` / `k` | 上一條 |
| `Home` / `End` | 第一條 / 最後一條 |
| `Enter` / `e` | 展開／收合程式碼節錄 |
| `x` | 這類我不管（展開確認列，focus 移到 `建立規則`） |
| `c` | 複製這一條 |
| `Tab` | 離開清單，到下一個區塊（不逐條 Tab） |

### 3.3 全域快捷鍵

只在沒有輸入框取得 focus 時生效。

| 鍵 | 動作 |
|---|---|
| `o` | 選擇資料夾 |
| `b` | 標記基準線 |
| `d` | 掃描變動 |
| `r` | 開始審查 |
| `/` | focus 篩選欄 |
| `f` | 切換「只看跨檔案」 |
| `s` | 切換略過條展開 |
| `m` | 開啟匯出預覽 |
| `?` | 快捷鍵表 |
| `Esc` | 見 §3.4 |

快捷鍵表是**這個站唯一的 modal**，因為它需要保護焦點且會被 Esc 關掉。
它有 `role="dialog" aria-modal="true"`、focus trap、關閉後還原 focus。

### 3.4 `Esc` 行為（由內而外，一次退一層）

1. 有 inline 編輯中（排除規則 chip、規則確認列）-> 取消該編輯
2. 程式碼節錄展開中 -> 收合最近展開的那一條
3. 匯出預覽開著 -> 關閉
4. 右軌抽屜開著（< 1024px）-> 關閉
5. 快捷鍵表開著 -> 關閉
6. 審查進行中 -> **不直接取消**，改為在按鈕旁展開 `取消審查？ [確定]`，再按一次 Esc 才取消
7. 都沒有 -> 什麼都不做（不清空、不重置、不返回）

第 6 點是刻意的：進行中的審查花了使用者真的錢，Esc 不能一鍵毀掉。

## 4. 失敗路徑總表

通則：錯誤**顯示在造成它的那個面板裡**（就地取代該面板的控制區），不用 toast、不用 modal。
表現形式是 §2 的「警示板」：`--fault-plate` 底、1px `--rule-x` 外框、`i-warn` 圖示（`--fg`）、
標題 `--fg` 15px/600、說明 `--fg-2` 14px、以及**一顆恢復動作按鈕**。
警示板沒有第二個色相（見 `docs/DESIGN-DIRECTION.md` §2.6）。

每一條錯誤文案的結構固定：**發生什麼 + 為什麼 + 你現在可以做什麼**。

### 4.1 瀏覽器不支援 File System Access API

不是錯誤，是能力差異，所以**不用警示板**，用支援晶片與狀態行。

偵測：`'showDirectoryPicker' in window`。

- 支援：晶片 `持久授權可用`（`--accent` 邊框）。狀態行 `File System Access API 可用，授權可續用`。
- 不支援：晶片 `單次選取模式`（`--fg-3` 邊框）。狀態行：

  > 這個瀏覽器沒有 File System Access API，所以無法記住資料夾授權。
  > 功能完整，只是每次回來都要重選一次資料夾。基準線與判讀規則仍會保留在本機。

  `選擇資料夾` 改綁 `<input type="file" webkitdirectory multiple>`（Safari 與 Firefox 都支援）。
  取得的是 `FileList`，每個 `File` 有 `webkitRelativePath`。基準線照樣可算，
  只是回訪時無法自動讀檔，需要重選（此時比對用的是新選到的檔案內容對舊雜湊）。

### 4.2 使用者取消了資料夾挑選器

`AbortError`。不顯示任何錯誤。畫面完全不動。這不是失敗。

### 4.3 選到的資料夾是空的，或全被排除規則濾掉

警示板在試件面板：

> **這個資料夾裡沒有可讀的檔案**
> 2,104 個檔案全部被排除規則濾掉了，或這個資料夾是空的。
> [ 檢視排除規則 ]  [ 換一個資料夾 ]

### 4.4 API key 錯誤（401 / `authentication_error`）

警示板在掃描設定面板，取代金鑰欄位：

> **這把 key 被供應商拒絕了**
> Anthropic 回覆 401 authentication_error。可能是 key 打錯、已被撤銷，或屬於另一個組織。
> [ 重新輸入 key ]

key **不會被自動清掉**（使用者可能只是貼漏一個字元），但 `已驗證` 標記會撤銷。

### 4.5 額度用完 / 速率限制（429、`insufficient_quota`、`rate_limit_error`）

兩種要分開講，因為復原方式完全不同：

- `insufficient_quota`：
  > **這個帳號沒有額度了**
  > 供應商回覆 insufficient_quota。這是帳單問題，不是設定問題。
  > 到 console.anthropic.com 加值後，這裡不用重設，直接再按一次就好。
  > [ 重試 ]

- `rate_limit_error` / 429 附 `retry-after`：
  > **打太快了，供應商要求等 18 秒**
  > 已收到的 5 條缺陷保留在畫面上。18 秒後會自動接續剩下的 3 個檔案。
  > [ 立即重試 ]  [ 停在這裡 ]

  自動重試**最多 3 次**，指數退避（`retry-after` 優先，否則 2s / 6s / 18s），
  倒數秒數顯示在按鈕上（真實倒數，不是假的）。

### 4.6 CORS 被擋 / 網路層失敗

瀏覽器對 CORS 失敗只給 `TypeError: Failed to fetch`，沒有細節。所以文案要涵蓋兩種可能：

> **請求沒有送到供應商**
> 瀏覽器層就被擋下了，通常是這三個原因之一：
> 1. 網路斷線或有 proxy 攔截
> 2. 廣告阻擋器 / 隱私擴充套件擋掉了 api.anthropic.com
> 3. 供應商暫時不接受瀏覽器直連
>
> 本站送出 Anthropic 請求時已帶 `anthropic-dangerous-direct-browser-access: true` 標頭，
> 這是瀏覽器直連的必要條件。若問題持續，先試著在無痕視窗開啟。
> [ 重試 ]  [ 檢視送出內容 ]

`檢視送出內容` 讓使用者能自己貼到 curl 驗證。這比任何安撫文案有用。

### 4.7 資料夾授權被撤銷

每次要讀檔前先 `await handle.queryPermission({ mode: 'read' })`。

- `granted`：直接讀。
- `prompt`：**不自動呼叫** `requestPermission()`（需要使用者手勢）。試件面板換成警示板：
  > **需要重新授權這個資料夾**
  > 瀏覽器重啟後授權會回到待確認狀態。基準線與判讀規則都還在。
  > [ 重新授權 nabe-orders ]
- `denied`：
  > **這個資料夾的授權被拒絕了**
  > 可以在網址列左側的圖示裡改回允許，或直接重新選一次資料夾。
  > [ 重新選擇資料夾 ]

審查進行中授權掉了：立刻停止送出剩餘批次，保留已收到的缺陷，顯示上述警示板，
並在按鈕旁註 `已完成 5/8，重新授權後可續掃剩下 3 個`。

### 4.8 IndexedDB 寫入失敗 / 配額滿（`QuotaExceededError`）

出現在右軌規則庫上方：

> **本機儲存空間滿了**
> 判讀規則沒有存進去。歷史報告佔用最多空間。
> [ 匯出全部規則為 JSON ]  [ 刪掉 3 個月前的歷史報告 ]

**先給匯出**，再給刪除。順序是刻意的：不能讓使用者在還沒備份前就被引導去刪東西。

另外，`navigator.storage.estimate()` 在使用量超過配額 80% 時，
狀態列的資產讀數後面出現一個 `i-warn` 圖示與 `儲存空間 82%`，點擊展開同一塊面板。

歷史報告有硬上限：**最多保留 40 次**，超過時最舊的自動刪除（規則庫永不自動刪）。
自動刪除發生時在狀態列寫一行 `已自動清除 1 份 5 月的歷史報告`。

### 4.9 模型回傳的東西不能用

四種，各自處理：

| 情況 | 處理 |
|---|---|
| 回傳非 JSON / JSON 截斷 | 盡量從串流中救出已完整的物件（逐一 `JSON.parse` 每個陣列元素），救不出來的部分顯示 `這一批的回覆格式不完整，已救回 4 條`，並提供 `重跑這一批` |
| 行號超出檔案範圍 | 該條標記 `(行號未能對應)`，嚴重度降一階，**仍然顯示**（情境描述可能還是對的），但匯出的 Markdown 也帶這個標記 |
| 引用了不在送出清單裡的檔案 | 該檔案路徑以 `--fg-3` 顯示並加註 `此檔案未在本次送出範圍內`。不隱藏，因為這往往是有價值的線索 |
| 回傳 0 條缺陷 | 不是錯誤。見 §7.2 |
| 回應被截斷（`stop_reason: max_tokens`） | 顯示 `這一批的輸出被長度上限截斷，已收到 6 條`，並提供 `把這一批拆成兩批重跑` |

### 4.10 使用者中途取消

`AbortController.abort()`。已收到的缺陷**全部保留**並照常排序、照常可匯出。
探傷帶上未掃到的欄位維持 `--strip-idle`，掃描游標停在原地不消失（顯示掃到哪裡）。
清單頂端一行：`已取消，掃了 5/8 個檔案。已用約 $0.11。[ 續掃剩下 3 個 ]`。

`續掃` 是真的續掃：只送剩下的檔案，結果合併進同一份報告。

### 4.11 基準線之後沒有任何變動

不是錯誤，是好消息，但介面不能只給一句「無資料」：

> **自 8/3 21:12 的基準線以來，沒有檔案變動**
> 如果 agent 剛剛才寫完，可能是基準線標記在那之後。
> [ 重新標記基準線 ]  [ 改為審查全部 318 個檔案 ]

第二顆按鈕會先顯示預估：`318 個檔案約 1.2M token，將分 21 批，估 $4.80`，需要再確認一次。
花錢的動作永遠要看到數字才能按下去。

### 4.12 單一檔案就超過預算

例如一個 180k token 的 `bundle.js` 漏掉排除規則。檔案挑選表該列顯示：
`單檔 182k 超過 60k 預算上限  [ 加進排除規則 ]  [ 只審前 60k ]`。
不靜默截斷，也不靜默跳過。

## 5. 招牌動效時刻：擊點（THE STRIKE）

**一句話**：一條缺陷從串流裡被解析出來的那一瞬間，探傷帶上對應的位置被畫上一個圈記，
一條引線從圈記垂下來，缺陷列在引線末端落定。

這是這個產品最值得投入資源的互動瞬間，因為它同時說了三件事：
**找到了**（回饋）、**在哪個檔案的哪一行**（階層）、**清單正在被建立**（狀態轉換）。
它取代了旋轉載入指示器：使用者不是在等，是在看儀器工作。

### 5.0 前置：試件上架（bed -> deck）

不是招牌時刻，是它的鋪陳。520ms（`--dur-4`）：

1. 量測網格**不重繪**（同一個背景層從頭到尾都在）。這句話賣的是「同一台儀器，現在裝上了東西」。
2. 四角角標從試件台的邊界，向外飛到工作台的四個角（`x` / `y`，`--ease-out`）。
3. 左軌從 `x: -24, autoAlpha: 0.6` 進入；右軌從 `x: 24, autoAlpha: 0.6` 進入，delay 0.06s。
   起始不是 `autoAlpha: 0`：內容在動效失敗時仍看得見。
4. 標題與說明文字 `autoAlpha` 降到 0 並 `y: -8`，200ms，先走。

reduced-motion：`data-stage` 直接切換，無過場，網格照樣連續。

### 5.1 掃描游標（審查進行中）

一條 1px `--accent` 垂直線，加上向左 24px 的亮度衰減拖尾（用 canvas `createLinearGradient`
在 `--accent` 與 `--strip-idle` 之間插值，**不是彩色光暈**，是亮度衰減）。

**位置是真實的**，不是計時器動畫：

```
progress = (已完成批次的檔案數 + 當前批次已收到 token / 當前批次預估 token) / 總檔案數
```

游標 x 座標 = `progress` 對應到探傷帶的橫向位置。用 `gsap.quickTo(cursor, 'x', {duration: 0.45, ease: 'power3.out'})`
讓位置更新平滑，但**值本身來自真實進度**。SSE 每收到一個 chunk 更新一次。

游標本身的移動用 `ease: "none"`（線性）是**合法的**：掃描是等速量測，
給它緩動會把儀器變成裝飾。這是整個專案唯一使用線性的地方，理由寫在這裡。

### 5.2 擊點（每條缺陷一次，420ms，`--dur-strike`）

觸發時機：SSE 串流裡一個完整的缺陷物件被 `JSON.parse` 成功的那一刻。
**不等整批結束**，所以缺陷是一條一條浮現的。

時間軸（GSAP timeline，全部走 canvas 繪製 + 一個 DOM 元素）：

| 時間 | 發生什麼 |
|---|---|
| 0.00s | 游標所在欄位閃一次亮度（`--strip-idle` -> `--strip-hit`，60ms 後開始回落） |
| 0.02s | 圈記開始畫：一個半徑依嚴重度而定的圓，用 `setLineDash` + `lineDashOffset` 做描邊繪出，260ms，`power3.out` |
| 0.12s | 圈記中心的十字準星畫出（兩條 5px 線，80ms） |
| 0.16s | 引線從圈記底部向下延伸到探傷帶底緣（`clip-path: inset()` 的 DOM 線段，180ms，`power4.out`） |
| 0.22s | 缺陷列插入清單：從 `y: -10, autoAlpha: 0.4` 到 `y: 0, autoAlpha: 1`，260ms，`--ease-settle`（極小 overshoot，像零件卡進定位） |
| 0.30s | 缺陷列的嚴重度標記做一次亮度脈衝（一次，不循環），140ms |
| 0.42s | 引線淡出（保留圈記）。清單計數 +1（數字用 `gsap.to({v}, {snap: {v: 1}})` 滾動一格） |

**跨檔案缺陷有額外的一段**：引線不是垂直的，而是先從第一個檔案的圈記橫向拉到第二個檔案的圈記
（一條 1px `--accent` 弧線，`quadraticCurveTo`，220ms 繪出），兩端都有圈記，然後才一起垂下引線。
這一段是整個介面最重要的兩百毫秒：**它是「跨檔案」這件事唯一的視覺證明**。

同時到達的缺陷排隊執行，間隔 90ms（`gsap.timeline` 佇列），避免同時十條一起爆開。
若佇列長度 > 6，間隔壓到 40ms 並跳過十字準星那一步，確保不塞車。

### 5.3 收尾（整批完成，觸發一次）

1. 游標在 200ms 內走到最右緣後消失（`autoAlpha`）。
2. 探傷帶底部出現每欄的缺陷數（`--font-mono` 11px），stagger 0.03s 由左至右。
3. 略過條從 `height: 0` 展開到自然高度，260ms，數字滾動到最終值。
4. 狀態列文字換成 `已完成，12 條，實際 $0.17`。
5. 右軌歷史刻度尺長出新的一根刻痕：從 `scaleY: 0` 到 1，`transformOrigin: bottom`，
   420ms `--ease-settle`。**這一根刻痕是留存迴圈的視覺句點**：使用者看到今天的柱子比上次矮。

沒有 confetti、沒有勾勾動畫、沒有音效。儀器做完事情就是安靜下來。

### 5.4 效能

- 探傷帶全部在單一 `<canvas>`（含 devicePixelRatio 縮放），圈記與網格畫在同一層。
  每幀只重畫**髒矩形**（游標移動的 40px 帶 + 新圈記的 32px 方框），不整張重繪。
- 引線是 DOM 元素（1px `div` + `clip-path`），因為它要跨越 canvas 與清單兩個區域。
  最多同時存在 6 條，用物件池復用。
- 缺陷列的進場只動 `y` 與 `autoAlpha`，不動 `height`（`height` 由 flex 自然決定，插入時瞬間佔位）。
- 目標 60fps。`gsap.ticker` 統一驅動 canvas 重繪，不另開 `requestAnimationFrame`。

### 5.5 `prefers-reduced-motion`

用 `gsap.matchMedia()`，`reduce` 分支直接 `return`，畫面停在預設可見狀態：

- 掃描游標：不做補間，每批完成時直接 `gsap.set` 跳位。
- 圈記：直接 `gsap.set` 畫出完整圈記與十字準星，無描邊繪製。
- 引線：不畫（它純粹是動態關聯線索）。跨檔案關聯改由**靜態弧線**永久顯示在探傷帶上，
  資訊不因為關掉動效而消失。
- 缺陷列：直接插入，無位移、無 autoAlpha 過場。
- 刻度尺：直接是最終高度。

CSS 端同步把 `--dur-*` 全部壓到 1ms（見 `tokens.css` 底部）。

## 6. 留存機制（本機資產在介面上長什麼樣）

這一節是整個專案存在的理由，所以它有自己的章節而不是散在各處。

### 6.1 三個資產，一條讀數

| 資產 | 存在哪 | 在介面的哪裡 | 使用者怎麼感覺到 |
|---|---|---|---|
| 基準線 | IndexedDB `baselines`（試件 id + 每檔 SHA-256） | 左軌第二格，顯示標記時間 | 第二次來不用重選、不用重算，一顆 `掃描變動` |
| 判讀規則 | IndexedDB `rules`（指紋 + 命中數 + 最後命中） | 右軌上半，常駐 | 清單頂端 `已自動略過 8 條`，每次都看得到 |
| 審查歷史 | IndexedDB `runs`（最多 40 筆，含完整缺陷清單） | 右軌下半刻度尺 | 柱子一次比一次矮 |

加上兩項會被記住的設定（存 `localStorage`）：排除規則、預算與模型選擇。

狀態列左段永遠顯示：`本機資產  基準線 1  判讀規則 16  歷史 5`。
這行字在每一個畫面狀態下都在，它是這個產品的心跳。

### 6.2 第一次的引導（規則庫是空的）

空的規則庫不能寫「暫無資料」。它要說明這個抽屜將來會裝什麼：

```
判讀規則  0

這裡會累積你的判讀。
第一次審查後，對任何一條缺陷按「這類我不管」，
同一類的東西之後就不會再出現。

現在是第 1 次。
```

`現在是第 1 次` 這一行會隨著歷史筆數改變：`現在是第 3 次`。
它建立了一個使用者會想要往上推的計數。

### 6.3 第 N 次比第 1 次省事，具體省在哪

介面要把這件事**寫出來**，不是讓使用者自己感覺。第二次以後進站，
主台在掃描結果出來前顯示一塊 `--well` 面板：

```
上次是 7/30，19 條，$0.21
這次已經幫你準備好：
  基準線在 8/3 21:12          11 個檔案有變動
  排除規則 7 條               已濾掉 2,104 個檔案
  判讀規則 16 條              上次擋掉 8 條重複的
  預算 60k，claude-sonnet-5   估 $0.19

[ 開始審查 ]
```

這塊面板在審查開始後被探傷帶取代。它只在**有歷史紀錄時**出現，
所以它本身就是「你來過」的證據。

### 6.4 規則命中回饋

每次審查結束，右軌規則列上，本次有命中的規則其命中數會**滾動增加**（`gsap.to` + `snap`），
並且該列左緣 1px `--accent` 標記亮起 1.2s。使用者看得到「我建立的規則今天做了工」。

沒有命中的規則不做任何動作（不變灰、不排到後面）。它只是今天沒事做。

### 6.5 匯出／匯入規則庫

`匯出 JSON` 產出的檔案結構固定並帶版本號：

```json
{ "format": "diff-warden-rules", "version": 1, "exportedAt": "...", "rules": [...] }
```

匯入時：格式不符給明確錯誤；重複指紋合併（命中數相加）；顯示 `匯入 12 條，其中 4 條已存在，已合併`。

## 7. 首次到訪與範例資料

### 7.1 空狀態是被構成的畫面，不是「暫無資料」

三個空狀態，各自不同：

| 位置 | 空狀態內容 |
|---|---|
| 試件台（`bed`） | §0.2 的完整首屏。它不是空狀態，它是這個產品的封面 |
| 探傷帶 | 1px 網格 + 四角角標 + 中央 `尚未掃描`。有網格與角標，所以看得出這是一台等著被裝載的儀器 |
| 缺陷清單 | 見 §7.2 |
| 規則庫 | §6.2 |
| 歷史尺 | 一條空軸線 + `第一次審查後，這裡會開始記錄` |

### 7.2 審查完成但 0 條缺陷

這是好結果，但不能只寫「沒有問題」，因為使用者會懷疑是不是壞了：

```
掃了 8 個檔案，沒有找到缺陷。

被略過的         5 條（依你的 16 條判讀規則）  ▸
實際用量         41.2k token，$0.15
模型             claude-sonnet-5

如果你覺得應該要有問題，可以：
[ 換 claude-opus-5 再掃一次 ]  [ 檢視送出內容 ]
```

`檢視送出內容` 讓使用者確認「檔案真的送出去了」。這是對「儀器是不是壞了」最直接的回答。

### 7.3 範例報告（`data-demo="true"`）

一份針對虛構但可信的小專案的完整審查報告。專案是 **`nabe-orders`**：
一個小型訂單後台（Node + Express + SQLite，前端 vanilla JS），10 個檔案，
剛被 agent 加上退款功能。這是接案者會遇到的真實形狀。

**12 條缺陷，3 條跨檔案，四個嚴重度都有。** 完整內容存在 `js/sample.js`：

| # | 嚴重度 | 跨檔案 | 位置 | 為什麼會爆 |
|---|---|---|---|---|
| 1 | 阻斷 | 是 | `server/lib/auth.js:41` + `server/routes/webhooks.js:12` | webhook 路由在 `requireSession` 之前註冊，端點沒有驗簽也沒有任何驗證。任何人 POST 一筆 `payment_intent.succeeded` 就能把訂單標記為已付款 |
| 2 | 阻斷 | 否 | `server/lib/money.js:18` | 金額用 `parseFloat` 乘 100 再取整，`19.99 * 100` 在浮點數下是 `1998.9999...`，退款路徑用 `Math.floor` 會少退 1 分，對帳永遠差幾塊 |
| 3 | 高 | 是 | `server/lib/db.js:57` + `server/jobs/reconcile.js:23` | 連線池上限 5，但對帳工作用 `Promise.all` 對 200 筆訂單同時開查詢。上線後第一次對帳會把池吃光，所有 HTTP 請求一起 timeout |
| 4 | 高 | 是 | `migrations/003_add_refunds.sql:7` + `server/routes/orders.js:145` | migration 把 `refunds.amount` 宣告成 `INTEGER`，寫入時傳的是 `money.js` 回傳的浮點數。SQLite 不會報錯，會靜靜截斷 |
| 5 | 高 | 否 | `server/routes/orders.js:88` | `ORDER BY ${req.query.sort}` 字串插值進 SQL。前面幾個參數用了 `?`，看起來已經安全，這一行沒有 |
| 6 | 高 | 否 | `web/js/checkout.js:132` | `fetch` 沒有 `catch`。網路斷線時按鈕永遠停在「處理中」，使用者只能重整，而重整會重送一次結帳 |
| 7 | 中 | 否 | `server/index.js:24` | 錯誤處理 middleware 註冊在路由**之前**，所有 route 丟出的錯誤都不會被它接到，直接變成沒有訊息的 500 |

## 8. 資料模型與本機儲存

IndexedDB 資料庫 `diff-warden`，version 1：

| store | keyPath | 內容 |
|---|---|---|
| `specimens` | `id` | `{ id, name, handle, kind: 'fsa'\|'picker', createdAt, lastOpenedAt }` |
| `baselines` | `specimenId` | `{ specimenId, markedAt, files: { path: { hash, size, mtime } } }` |
| `rules` | `fingerprint` | `{ fingerprint, category, messagePattern, filePattern, hits, createdAt, lastHitAt }` |
| `runs` | `id` | `{ id, specimenId, at, model, provider, defects[], suppressed[], usage, cost }` |

`localStorage`：

| key | 內容 |
|---|---|
| `dw.key.anthropic` / `dw.key.openai` | API key（明文。瀏覽器沒有更安全的選項，README 會誠實說明） |
| `dw.provider` / `dw.model` / `dw.budget` | 設定 |
| `dw.excludes.<specimenId>` | 排除規則 |

`FileSystemDirectoryHandle` 可結構化複製，所以能直接 `put` 進 `specimens`。
這是整個持久化策略的技術前提，已驗證。
