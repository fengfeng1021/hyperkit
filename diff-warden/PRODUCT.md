> 這份文件寫的是「這個東西為什麼存在、誰在什麼情緒下打開它、哪裡不能出錯」。
> 互動規格在 `docs/INTERACTION.md`，視覺契約在 `docs/DESIGN-DIRECTION.md`。

## 1. 被付錢的那件工作

> 「Cursor / Claude Code 幫我寫了三千行，我不知道哪裡會爆，也沒有人可以幫我看。」

使用者買的不是「AI 審查」這個功能。他買的是兩樣具體的東西：

1. **一份可以拿去給別人看的缺陷清單**。有檔案、有行號、有嚴重度、有「什麼情況下會爆」。
   可以貼進 issue、可以寄給合夥人、可以附在交付給客戶的驗收信裡。
2. **不用把原始碼上傳給第三方**。接案者簽了 NDA，公司程式碼有保密條款。
   「程式碼沒有離開這台電腦」在採購對話裡是一句可以寫下來的事實，不是隱私話術。

付費證據（`docs/PORTFOLIO-V2.json`）：CodeRabbit ARR $40M、一年成長 700%、Enterprise 起價 $15,000/月；
Greptile 2,000+ 付費客戶。人力側：Upwork 上「程式碼審查／救火」已是獨立分類，$150-400/小時。

**要誠實標記的推論**：上述兩家的錢都來自有 PR / CI 流程的團隊。
「沒有 PR 流程的單人開發者也會付錢」是從相鄰市場推論的，不是直接觀察到的。
這個推論如果錯，這個題目就沒有市場，而不是介面做得不夠好。

## 2. 使用者是誰，在什麼情境下打開它

### 誰

三種人，優先序如此：

1. **接案的獨立開發者**。手上兩三個案子同時跑，用 Cursor 或 Claude Code 把速度拉起來。
   他的痛不是「寫不出來」，是「交出去以後客戶回報一個他從沒想過的情況，然後他免費加班三天」。
2. **兩到四人小團隊的技術負責人**。沒有專職 reviewer，PR 都是自己 approve 自己的。
   他知道這樣不對，但請一個人來 review 不划算。
3. **有一定程式底子、但正在做超出自己熟悉範圍的東西的人**。
   例如前端出身、被迫寫金流後端。他看得懂程式碼，但不知道自己不知道什麼。

### 在哪，剛做完什麼，什麼情緒

深夜或傍晚，家裡或咖啡廳，一台筆電。旁邊那個視窗還開著 Cursor，游標還停在 agent 剛寫完的最後一行。

他剛剛做完的動作是：接受了一大批 diff。他按了 Accept All，或按了十幾次 Accept。
現在螢幕上有三千行他沒有逐行讀過的程式碼。它跑起來了。測試（如果有的話）過了。

情緒不是恐慌，是**一種說不出來的不踏實**。他知道「跑得起來」跟「不會爆」是兩件事。
他也知道自己現在沒有精神逐行看完，而且就算看完，他也會漏掉跨檔案的問題，因為那需要同時把六個檔案放在腦子裡。

他此刻最不想要的是：再跟一個聊天視窗對話。他今天已經打了太多字了。

### 一次真實的 session

```
21:47  agent 跑完，接受了 3,100 行的變更，橫跨 11 個檔案
21:48  切到瀏覽器分頁（這個站已經開著，因為上週用過）
21:48  資料夾授權還在，直接按「掃描變動」
21:49  看到 11 個變動檔案，儀器已經照變動量排好序，估 47k token，估 $0.19
21:49  按「開始審查」
21:50  第一條缺陷落下：webhook 路由掛在驗證中介層之前
21:51  掃描結束。12 條，其中 3 條跨檔案。已自動略過 8 條（他上週標記過的規則）
21:52  逐條看，把兩條「這是我刻意的」按掉，判讀規則變成 16 條
21:55  匯出 Markdown，貼進自己的 issue tracker
21:56  回到 Cursor，把第一條貼給 agent 說「修這個」
```

**整段沒有一次對話**。這件事本身就是產品定位。

## 3. 這個介面必須證明的四件事

### 3.1 這是儀器，不是聊天

第一眼就要看出來。畫面上沒有輸入框等你打字、沒有訊息氣泡、沒有頭像、沒有「思考中」。
有的是：一張試件（你的資料夾）、一組刻度（預算與挑檔）、一條掃描帶、一份缺陷清單。

如果使用者第一眼的反應是「這跟我在 Cursor 裡問一句有什麼差別」，這個產品就死了。
所以形式必須先講清楚：**輸出是一份報告，不是一段回覆。**

### 3.2 你的程式碼沒有離開這台電腦（而且我能證明給你看）

不是在角落寫一行「隱私優先」。要具體：

- 首屏就寫出資料流向：`本機資料夾 -> 你的瀏覽器 -> 你自己的 API key -> 供應商`。沒有第四個節點。
- 送出前顯示**實際會被送出的檔案清單與位元組數**，使用者可以逐個取消勾選。
- 「檢視送出內容」可以直接看到將要送出的 request payload 的檔案部分。
  這是唯一能讓有 NDA 的人放心的做法：讓他自己驗。

### 3.3 這個資產在累積

第五次用必須明顯比第一次省事，而且使用者要**看得到**這件事，不是只是感覺到。
三個本機資產：**基準線**、**判讀規則**（誤報記憶）、**審查歷史**。
右軌永遠在，永遠顯示這三個東西目前的數量。狀態列上有一行讀數：

```
本機資產  基準線 1  判讀規則 16  歷史報告 5
```

而且每次審查結束，清單頂端有一條：**「已依你的 16 條判讀規則自動略過 8 條」**，可展開、可回收。
這是使用者不會換工具的原因，所以它必須在最貴的版位上。

### 3.4 花多少錢，事前就知道

BYOK 產品的信任在這裡建立或崩塌。送出前必須顯示：
選中檔案數、估算 token（輸入／輸出分開）、估算美金花費、分幾批。
估算完成後與實際用量對照（供應商回傳 usage），顯示**實際花費**，並記進歷史。
估太多或估太少都要誠實顯示落差，不能只在估準的時候給數字。

## 4. 絕對不能出錯的地方

### 4.1 不能把使用者的 key 送到任何第三方

`localStorage` 存 key，只在 `fetch` 到 `api.anthropic.com` / `api.openai.com` 時放進標頭。
專案內零分析、零外部腳本、零錯誤回報服務。GSAP 是唯一的外部資源，來自 CDN，且不接觸 key。
這一條寫在 README 與 `docs/INTERACTION.md`，並且要能被使用者在 Network 分頁裡自己驗證。

### 4.2 不能對瀏覽器支援說謊

File System Access API 只有 Chromium 系（Chrome / Edge / Opera）有。Firefox 與 Safari 完全沒有。
**這件事寫在首屏**，不是藏在 FAQ。而且 Firefox / Safari 使用者不能只看到一句「不支援」：
他們走 `<input type="file" webkitdirectory>` 這條路，功能完整，只是每次都要重選資料夾。
介面要明確告訴他們少了什麼（持久授權），以及那代表什麼（每次重選）。

### 4.3 不能弄丟使用者的判讀規則

判讀規則是這個產品唯一的護城河。IndexedDB 寫入失敗、配額滿、或使用者清瀏覽器資料都會歸零。
所以：規則庫必須可以**匯出成 JSON 並匯入**，而且這個按鈕不能藏在三層選單裡。
IndexedDB 寫入失敗時要立刻在右軌顯示，不能靜默失敗。

### 4.4 不能產生看起來很專業但是假的缺陷

模型會編造行號。所以每一條缺陷的行號都要**在本機驗證過**：
讀該檔案、確認行號在範圍內、把該行內容抓出來一起顯示。
行號超出範圍的缺陷標記為「行號無法對應」並降級，不是照樣顯示。
這是「可以拿去給別人看」的前提，一條假行號就毀掉整份報告的可信度。

### 4.5 不能在第一次到訪就要求任何東西

沒有 key、沒有資料夾、不是 Chromium，都要能在十秒內看到完整的輸出長什麼樣。
`看範例報告` 是首屏兩個按鈕之一，不是次要連結。範例報告是一份完整的、
針對虛構但可信的小專案的 12 條缺陷清單，其中 3 條跨檔案，可以展開、可以匯出、可以按「這類我不管」
（在範例模式下按下去會示範規則怎麼建立，並明確標示這是範例）。

## 5. killRisk：真正的對手是使用者已經裝好的 Cursor

`PORTFOLIO-V2.json` 寫得很清楚：對手不是 CodeRabbit，是**免費、已安裝、還能直接改程式碼的 agent**。
「叫 agent 審查一下」是零成本替代方案。這個題目要活，只能靠 agent 做不好的三件事。

介面必須把這三件事做得**明顯到不需要解釋**：

### 5.1 跨檔案的結構化缺陷清單

agent 在對話裡回你一段散文，你要自己讀完、自己判斷、自己記住。而且它一次只看得到你貼給它的檔案。

介面上的具體做法：

- 缺陷是**列**，不是段落。固定欄位：嚴重度標記 / `檔案:行號` / 類別 / 標題 / 為什麼會爆的情境。
- **跨檔案缺陷排在最上面**，並用引線把兩個檔案位置連起來。有「只看跨檔案」的篩選。
- 送出的 prompt 明確要求跨檔案分析，且送出時附上被選檔案之間的 import / require 關係圖（本機解析，非語意索引）。
- 掃描帶（探傷帶）上，跨檔案缺陷畫成一條連接兩個檔案欄位的引線。這是視覺上最強的一句話：
  **這個東西看得到檔案之間的關係。**

### 5.2 可累積的誤報記憶

agent 每次都從零開始。你上次跟它說「這個我不管」，下次它照樣講一遍。

介面上的具體做法：

- 每條缺陷右側有 `這類我不管`。按下去產生一條規則指紋：`類別 + 正規化訊息 + 檔案模式`。
- 規則庫在右軌**常駐**，顯示每條規則的命中次數與最後命中日期。
- 每次審查結束，清單頂端顯示 `已依你的 N 條判讀規則自動略過 M 條`，可展開回收。
- 審查歷史用刻度尺呈現：每次審查一根刻度，高度是缺陷數。使用者可以**看到雜訊在下降**。
- 規則可匯出 / 匯入 JSON。這既是防資料遺失，也是「這是我的資產」的心理錨點。

### 5.3 可以交給別人看的報告檔案

agent 給你的是聊天記錄。你不會把聊天記錄寄給客戶。

介面上的具體做法：

- `匯出 Markdown` 是一級動作，跟 `開始審查` 同一個層級。
- 報告有標頭：專案名、審查日期、審查範圍（幾個檔案、哪些、為什麼是這些）、
  使用的模型、已套用的判讀規則數。**審查範圍聲明**是這份文件能被信任的原因。
- 匯出前有預覽。使用者看得到成品才會願意寄出去。
- 報告底部有一行來源標註：由本機審查產生，原始碼未上傳。

### 5.4 如果這三件事的價值感不夠明顯，這個題目會死

所以首屏必須有一個**對照**，直接把話講開，而不是迴避：

| 叫 agent 審查一下 | 這台儀器 |
|---|---|
| 回你一段散文，要自己讀完 | 一份有檔案、行號、嚴重度的清單 |
| 每次從零開始，誤報講一百遍 | 你標記過的，之後自動不顯示 |
| 聊天記錄不能寄給客戶 | 一份 Markdown 報告，含審查範圍聲明 |

這張表是誠實的，不是行銷話術：它承認 agent 也能審查，只是輸出形式不同。
承認對手的能力比假裝對手不存在更有說服力。

## 6. 定價與商業模式（第一版不實作，但介面不能擋住它）

一次性授權 US$49，Lemon Squeezy 收單，Ed25519 簽名離線授權碼，公鑰內嵌，WebCrypto 驗簽。
**第一版不做授權閘門**，全功能開放。

誠實面：純靜態站無法做用量計量與強制閘門，授權碼一定可破。
真實 LTV 天生低於 CodeRabbit 那種按人頭月費。這一項換不到訂閱收入，
只能換高轉換的低摩擦一次性購買。這是清醒的取捨，不是疏忽。

介面上要預留的位置：狀態列右端一個授權狀態欄位（第一版顯示 `開放版本`）。
不做任何「升級」彈窗、不做倒數、不做功能鎖圖示。

## 7. 範圍界線（第一版明確不做）

`PORTFOLIO-V2.json` 的 firstVersionScope 已經寫死，這裡只補上「為什麼」：

| 不做 | 為什麼 |
|---|---|
| 整 repo 語意索引 | 需要 embedding 與向量檢索，純前端做得到但會吃掉全部時間，且第一版的價值來自變動檔案而非全庫 |
| 解析 `.git` | isomorphic-git 兩週起跳，而且非 git 資料夾（agent 常常直接寫在沒有 git 的資料夾）用不到 |
| GitHub / GitLab 串接 | 等於把使用者拉回「有 PR 流程」的世界，而這個產品的差異化正是不需要 PR |
| CI 整合 | 純靜態站不可能 |
| 自動套用修補 | 這是 Cursor 的主場，正面對撞必輸，而且會讓「不改你的程式碼」這個信任基礎消失 |
| 多 repo | 一次一個試件。多試件是儀器房的事，不是儀器的事 |
| 行內編輯 | 使用者旁邊就開著編輯器。在這裡編輯只會讓兩邊不同步 |

**成功判準**（照抄 firstVersionScope，這是驗收標準）：

在一個 300 檔案的真實專案上，agent 剛產出一批程式碼後，
90 秒內、花費使用者 $0.30 以內，產出至少一條跨檔案的缺陷而且使用者同意它是真的；
同一 repo 第二次跑時，重複的誤報數量明顯下降，且 UI 顯示「本次已自動略過 12 條你標記過的」。
