## 1. 獨特機制（一句話）

ChatVault 在瀏覽器分頁裡把你的 AI 對話匯出檔編成一座可查詢的卡片目錄：自建的 BM25 倒排索引在本機建立，ChatGPT 的分支樹被還原成可切換的線性閱讀路徑，全程沒有一個 byte 離開這台電腦。

拆成三個可驗證的斷言：

1. **零上傳、零安裝。** 不是「我們不看你的資料」，是「頁面根本沒有可以送出資料的端點」。網路請求清單在站內公開，使用者可以用 DevTools Network 面板逐條核對。
2. **分支是被還原的，不是被丟掉的。** ChatGPT 的 `mapping` 是一棵樹。所有競品都把它壓平，代價是重複訊息或憑空消失的回答。ChatVault 從 `current_node` 往回走 parent 鏈得到正確的線性對話，同時索引所有分支，並在分岔點給出切換器。
3. **搜尋有排序理由。** 不是 substring match。BM25 打分、片語、排除詞、角色/日期/來源篩選，命中片段帶上下文，點擊直接跳到對話原文的那一則訊息。

## 2. 受眾的真實使用場景

### 誰

每天用 AI 工作的人。開發者、研究生、技術寫作者、獨立顧問。共同特徵：使用 12 個月以上，累積 800 到 4,000 則對話，付費訂閱至少一家，而且**已經至少一次找不到自己知道存在的那段對話**。

不是「對 AI 好奇的人」。是已經把 AI 當工作記憶體，然後發現這塊記憶體沒有索引的人。

### 在哪、什麼時候

兩個具體時刻，介面必須同時服務：

**時刻 A：封存日。** 週末晚上，桌機，剛從 ChatGPT 設定頁按下 Export data，收到信，下載了一個 340 MB 的 zip。這個人此刻是好奇加上一點忐忑：檔案很大，過去試過的工具都打不開。他想看到的第一件事是「它真的讀進去了」，而且要快到讓他相信這不是假動作。

**時刻 B：找回來。** 週三下午三點，工作中被打斷。他正在寫一段程式，記得三個月前跟 AI 討論過某個 rate limit 的退避策略，記得對方給過一段程式碼，但記不得是哪一次對話、也記不得確切用詞。他只有一個模糊的關鍵字和一段時間範圍。這個時刻的容忍度是**十五秒**。超過十五秒他就回去重問 AI 一次，ChatVault 就輸了。

### 什麼情緒

兩種情緒交錯，缺一不可解：

- **挫折。** 「我知道它在裡面但我找不到。」原生搜尋只做 exact keyword match，200 MB 的 HTML 匯出檔瀏覽器直接卡死，裝過的 Chrome 擴充功能全都壞掉。這種挫折是累積的，不是一次的。
- **戒備。** 這些是他問過最蠢的問題、最私密的想法、公司的內部設計、還沒公開的計畫。「上傳到我們的伺服器就能搜尋」對這個受眾不是便利，是紅線。他會打開 DevTools 檢查。

一般工具只解第一種。ChatVault 必須讓第二種在**進站三秒內**就被解掉，否則第一種根本沒機會被解。

## 3. 這個介面必須證明什麼

四件事，每一件都必須是可觀察的事件，不是文案宣稱。

**證明它沒有上傳。**
- 站內公開完整的網路請求清單：字型（fonts.googleapis.com / fonts.gstatic.com）、GSAP（cdn.jsdelivr.net）、以及「只有在你點下 Enable meaning search 之後才會發生」的模型下載。除此之外零請求。
- 索引完成的計數器結尾固定是 `Nothing left this tab.`
- 首次載入完成後可以中斷網路繼續使用（字型與 GSAP 已快取），這件事寫在說明裡並且是真的。

**證明它打得開大檔。**
- 進度是真的位元組進度，不是假動畫。
- 解析期間主執行緒不卡：畫面持續回應捲動與輸入，因為解析在 Web Worker，且 JSON 是分片串流解析，永遠不會 `JSON.parse` 整個檔案。
- 索引邊建邊可用：第一批對話進來就能點開閱讀，不必等到 100%。

**證明搜尋真的比原生好。**
- 打字時每個字元都有回饋，結果在 120ms 內重排。
- 每一筆結果顯示命中的那句話，關鍵字被標起來，點下去跳到對話原文的正確位置並保持標記。
- 片語 `"rate limit"`、排除 `-python`、`role:human`、`after:2025-03` 全部真的生效，而且語法說明就在搜尋框旁邊，不是藏在文件裡。
- Expanded 模式加進去的每一個延伸詞都以可刪除的 chip 顯示出來。使用者永遠知道系統為什麼給他這個結果。

**證明它是一個目錄，不是一個檔案總管。**
- 統計面板不是裝飾，它回答「這兩年我到底在問什麼」。詞頻經過 stopword 過濾與 IDF 加權，出來的是主題不是介系詞。
- 標籤沿著卡片頂緣凸出來，抽屜在左邊，卡片在中間，內文在右邊。空間佈局本身就在教使用者這是一個索引系統。

## 4. 絕對不能出錯的地方

依嚴重度排序。第一項出錯等於產品失效，不只是體驗變差。

### 4.1 分支還原錯誤（最嚴重）

走錯 `mapping` 的樹會產生**使用者從來沒說過的對話**。這比慢一百倍還嚴重，因為使用者無法察覺，而且會據此做判斷。

硬性規則：
- 線性路徑只能由 `current_node` 沿 `parent` 往上走，再反轉。**絕對不允許**用 `Object.values(mapping)` 依 `create_time` 排序來當作對話順序。那是所有壞掉的競品的做法。
- 分支切換後重算路徑：前綴取到分岔點的 parent，然後從選中的兄弟節點往下走，每個岔口取 `create_time` 最大的子節點直到葉節點。
- 每一則訊息在 UI 上都可以回答「這是不是目前路徑上的」。搜尋命中在非當前分支時，結果卡上標示 `on an alternate branch`，點進去自動切到那條分支。

### 4.2 資料損毀與誤刪

- IndexedDB 寫入一律在交易裡，每 200 筆一個交易。交易失敗整批回滾，不留半筆。
- 重複匯入必須**去重合併**，不是覆蓋。去重鍵：`source + conversationId`；沒有 id 的格式退回 `hash(title + createdAt + firstMessageText)`。
- 清空金庫是唯一具破壞性的動作，必須要求使用者輸入 `delete` 才會執行，而且明講「這個動作無法復原，你的匯出檔案不受影響」。
- 任何解析失敗都不得回頭刪掉已經寫入的資料。截斷檔案的復原路徑是「保留已讀到的部分」。

### 4.3 隱私宣稱造假

任何一個未宣告的網路請求都會摧毀整個產品。包含：
- 不得有 analytics、不得有 error reporting、不得有 favicon 以外的第三方資源。
- 語意搜尋的模型下載必須在明確的確認對話之後才發生，並且事先告知來源網域與下載大小。
- Google Fonts 與 GSAP CDN 必須被明確列出，不能靠使用者自己發現。誠實地說「這兩個請求存在，它們不帶你的資料」比假裝沒有更有說服力。

### 4.4 大檔造成分頁凍結

- 主執行緒任何一次同步工作超過 50ms 都算失敗。
- 虛擬捲動必須真的虛擬：DOM 節點數上限固定，不隨資料量成長。
- 索引在記憶體裡用 typed array，不用巢狀物件。20 萬則訊息的 posting list 必須是 `Int32Array` + `Uint16Array` + delta 編碼的位置陣列。

### 4.5 搜尋結果錯誤

- 片語搜尋若做成「所有詞都出現」而不是「相鄰出現」，是錯的功能，比沒有更糟。位置索引必須真的存在並被檢查。
- 排除詞必須在打分之前先剔除文件，不是事後過濾分數。
- 篩選條件與查詢詞的交集為空時，必須明講是哪一個條件造成的，並提供逐條移除的入口。

## 5. 競品在哪裡讓使用者失望

| 競品類型 | 具體失敗 | ChatVault 的回應 |
|---|---|---|
| 官方原生搜尋（ChatGPT / Claude 網頁） | 只做 exact keyword match，沒有排序、沒有時間篩選、沒有跨對話的片語搜尋。使用者原話：搜尋「基本上沒用」 | BM25 排序 + 片語 + 排除詞 + 角色/日期/來源篩選，全部在同一個輸入框 |
| Google Takeout / 官方匯出檔本身 | 200 MB 的 HTML 檔瀏覽器開不起來；`conversations.json` 是一坨無法閱讀的樹狀結構 | 串流分片解析 + Web Worker，位元組級進度，第一批進來就能讀 |
| Chrome 擴充功能 | 「沒有一個能正常運作」。更新後壞掉、要權限、來源不透明 | 沒有安裝、沒有權限請求、原始碼就是這個資料夾 |
| CLI 工具（echomine、ChatKeeper 等） | 要裝 Python 或 Node，要跑指令，非工程師直接出局 | 打開網頁、拖入檔案 |
| 上傳型 SaaS 檢視器 | 要把最私密的對話上傳到別人的 Supabase | 資料在 IndexedDB，網路請求清單公開可核對 |
| 大多數檢視器（含付費） | 把 `mapping` 樹壓平，分支訊息重複或消失 | 正確走 parent 鏈，分支可切換，非當前分支也被索引且標示清楚 |
| 幾乎所有工具 | 只給你一個列表，不告訴你「你這兩年在問什麼」 | 統計面板用 IDF 加權詞頻，輸出的是主題不是「the / and / 我覺得」 |

**共同的失望根源：** 這些工具全都把「打開匯出檔」當成終點。使用者要的不是檢視器，是一個**索引**。檢視器讓你看到你已經知道位置的東西；索引讓你找到你只記得一半的東西。ChatVault 的整個設計語言（抽屜、卡片、凸出的標籤、交叉索引）都在說同一件事：這是索引，不是檢視器。

## 6. 不做什麼

明確排除，避免範圍蔓延與假功能：

- **不做帳號、不做同步、不做分享連結。** 任何一個都會迫使資料離開這台電腦，與核心宣稱直接衝突。
- **不做編輯。** ChatVault 是唯讀的封存工具。可以標記、可以匯出，不能改寫歷史紀錄。
- **不做即時串接 API。** 不代發訊息、不接續對話。那是另一個產品。
- **不做付費牆。** PORTFOLIO.json 描述了 Pro 買斷方案，但這個站的目標是證明技術與設計，任何被鎖住的功能在這裡都等於「空殼」。全部功能開放，不放 license 驗證。
- **不做深色模式。** 見 DESIGN-DIRECTION.md 第 6 節，這是刻意的決定，不是遺漏。
