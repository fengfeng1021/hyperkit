# Mockup Loom / 情境織機 - 產品真實

介面語言：英文。文件語言：繁體中文。所有引號內的字串是要逐字出現在介面上的英文原文，不可翻譯。

## 1. 獨特機制，一句話

> 使用者的設計圖不是「貼」在商品照上，而是被程式生成的布料高度場（displacement field）彎折之後，
> 再與同一張高度場算出來的法線、環境遮蔽、縫線遮罩一起合成，
> 所以圖案會沿著皺褶起伏、被縫線吃掉一點邊緣、在光源轉向時整面牆一起換陰影。

一句話的商業版本（可放介面）：
> "The print bends with the cloth, not on top of it."

### 為什麼這個機制值得存在

免費工具做的是「平貼」：把 PNG 用 CSS transform 疊到商品照上，套一層 multiply 就交差。
一眼假的原因不是解析度，是**圖案在皺褶上依然筆直**。人眼對這件事極度敏感，因為現實中不存在筆直穿過皺褶的印花。
付費工具（Placeit 等）做得對，但把批次鎖在付費牆後面，而賣家真正的痛點是「50 個設計 × 10 個模板 = 500 張圖」。

本站把兩件事同時給出來：**位移是真的，批次是免費的**。

### 素材誠實聲明（不可省略）

本站沒有攝影素材。所有模板（底圖、displacement map、AO/陰影層、縫線遮罩）
都是用 Canvas 2D + 自行實作的 value noise / fbm / domain warping 在瀏覽器裡即時生成的。
介面必須在**模板選擇區**與**每一張匯出圖的 MANIFEST 檔**裡明說這件事，用字：

- 模板選擇區標題旁：`"Procedural templates. Generated in your browser, not photographed."`
- MANIFEST.txt 第一行：`"Templates in this export are procedurally generated (noise-based), not photographic."`

這不是免責聲明，這是產品的一部分：程式生成代表模板是**可重現的**（每個模板有 seed），
也代表使用者可以拿到「同一件 T 恤但布料皺褶不同」的變體，這是攝影模板做不到的。

## 2. 受眾與真實使用場景

### 主要受眾：獨立商品賣家（print-on-demand seller）

不是設計師。是「有一批圖案要上架」的人。他的設計能力可能只到會用 Canva 排字，
但他一個月要上 20 到 60 個新款，每一款要 6 到 10 張情境圖才有轉換率。

**誰**：Etsy / Redbubble / Shopify 上賣 T 恤、托特包、貼紙的個人賣家，多半一人公司。
**在哪**：家裡的桌子，外接螢幕或筆電，室內燈或白天窗邊光。
**什麼時候**：上架前的最後一段流程。設計已經做完了，去背也做完了（很可能剛從 cutout-forge 過來），
現在卡在「要生一堆商品圖」這一步。這通常發生在晚上，而且他已經有點煩了。
**什麼情緒**：**不耐煩，而且抱著懷疑**。他試過三個免費線上 mockup 工具，全部都是平貼，圖出來很假，
或者做到第 3 張就跳出「Upgrade to export without watermark」。他點進來的心態是「再給你 30 秒」。

所以第一屏必須在 30 秒內證明兩件事：**位移是真的**、**批次不收錢**。

### 次要受眾：小型品牌的社群經營者

要在週會前生出這一季 8 個圖樣在 4 個品項上的預覽圖給主管挑。
他不在乎技術，他在乎「一次選完、一次匯出、檔名整齊到可以直接丟進共用雲端」。
所以 ZIP 的資料夾結構與自動命名對他而言比 shader 重要。

### 明確不是我們的受眾

- 要做真實產品打樣的服裝廠：他們需要真實色票與尺寸規格，本站不提供。
- 需要 3D 旋轉檢視的人：本站是 2D 合成，不做 3D。介面不假裝有這功能。

## 3. 這個介面必須證明什麼

依重要性排序。每一項都必須在**不需要閱讀說明文字**的情況下被證明。

1. **位移是真的，而且差異肉眼可見。**
   證明方式：`FLAT` / `WOVEN` 開關。0.3 秒內同一張圖從筆直變成沿皺褶彎折。
   驗收標準：把開關前後兩張截圖並排，非技術人員能在 2 秒內指出哪張是假的。
   如果做不到這個差異，這個產品沒有理由存在。

2. **這是真的在運算，不是預先做好的兩張圖。**
   證明方式：光源方位可以拖曳，陰影即時重算；改布料顏色、改混合模式、改設計位置，位移都跟著重算。
   一個預錄的動畫不可能對任意輸入都成立，使用者換上自己的圖就知道了。

3. **批次真的跑得完，而且免費。**
   證明方式：批次模式顯示 `N designs x M templates = K renders`，跑完就是跑完，沒有浮水印、沒有數量上限提示、沒有升級牆。
   進度以「已完成 / 總數」的實數顯示，卡片算完一張補一張。

4. **檔案出來就能用。**
   證明方式：匯出前先把 ZIP 的資料夾樹**畫出來給使用者看**，包含實際檔名。
   使用者在按下 Export 之前就知道解壓縮後會長什麼樣。

5. **設計稿不會離開這個分頁。**
   證明方式：沒有任何 network 請求會送出使用者的圖（除了字型與 GSAP 的 CDN，這兩者在載入時就完成）。
   介面上以一行小字說明，放在設計上傳區下方：
   `"Your designs stay in this tab. Nothing is uploaded."`
   這句話必須是真的：不做分析追蹤、不做錯誤回報上傳、不寫進 localStorage。

## 4. 絕對不能出錯的地方

| 出錯的地方 | 為什麼致命 | 防線 |
|---|---|---|
| 位移開關切過去看不出差別 | 產品的全部價值就是這 0.3 秒。沒有差別 = 沒有產品 | 位移量的預設值必須調到「明顯但不扭曲到看不懂圖案」。開發時用一張直線網格圖當校正卡，直線必須明顯彎曲 |
| 匯出的 ZIP 打不開 | 賣家跑了 500 張、等了兩分鐘，結果檔案壞掉。他不會再回來 | ZIP 寫入器自己實作（STORE 模式），CRC32 必須逐檔驗算；匯出前先寫一個 1 檔的測試 ZIP 驗證 EOCD 位移 |
| 匯出的圖有透明破洞或黑邊 | 上架後才發現，等於害他被客訴 | 設計圖取樣在超出 [0,1] 時 alpha 必須硬歸零，不可用 CLAMP_TO_EDGE 拖出色條；輸出一律不透明背景 |
| 批次跑到一半分頁卡死 | 500 張是常態，不是極端情況 | 分批排程（每個 animation frame 最多算 1 張），中途可暫停與取消，記憶體只保留 blob 不保留 ImageData |
| 顏色判斷被介面背景污染 | 賣家要用這張圖判斷「這個綠印在灰 T 上好不好看」 | 畫布舞台是唯一 R=G=B 完全中性的表面（`#767676`），周圍 chrome 才容許 3 到 5 階的暖偏移 |
| WebGL2 不支援時整站掛掉 | 一部分使用者用舊瀏覽器或關閉硬體加速 | 降級模式：Canvas 2D 平貼合成 + 匯出仍可用，並用一行橫幅明說少了什麼 |
| 使用者的設計被吃掉 | 他丟了 50 個檔案，重整就沒了 | 設計不寫入儲存是刻意的隱私決定，所以離開頁面前必須以 `beforeunload` 提醒；只在有未匯出成果時提醒 |

## 5. 競品在哪裡讓使用者失望

以下是產品定位的直接依據。每一條都對應到我們的一個具體設計決定。

### 5.1 免費線上 mockup 產生器（各種 "free mockup generator"）

**失望點**：平貼。圖案穿過皺褶時依然筆直，商品圖一眼假，上架後轉換率低。
使用者不會說「這是平貼」，他會說「怎麼看起來就是很像合成的」。
**我們的回應**：把「平貼 vs 位移」做成第一個、也是最大的一個控制項。不是藏在設定裡的選項，是舞台正下方的主控制。

### 5.2 Placeit / 類似訂閱制服務

**失望點**：模板品質好，但批次與去浮水印綁在訂閱後面。賣家的使用頻率是「每次上新品」，
一個月可能只用兩天，訂閱制對他而言是純虧損。而且退訂之後過去產出的圖有授權疑慮。
**我們的回應**：批次無限、無浮水印、無帳號。營收線放在「模板包」而不是「功能鎖」。
介面上永遠不出現 `Upgrade`、`Pro`、`Unlock` 這類字眼擋在流程中間。

### 5.3 Photoshop 動作 / 批次腳本（Etsy 上真的有人在賣）

**失望點**：要有 Photoshop、要會裝動作、要會設定批次資料夾、跑錯一個設定就要重跑。
而且 smart object 置換一次只能一個模板。
**我們的回應**：零安裝、零設定檔。批次的心智模型只有兩個清單相乘：選幾個設計、選幾個模板，其餘自動。

### 5.4 Canva 之類的通用設計工具

**失望點**：有 mockup 素材，但那是「圖片框」，完全沒有布料變形。而且無法批次，
更無法用一套命名規則匯出成結構化資料夾。
**我們的回應**：命名規則用 token 樣板（`{design}__{template}__{w}x{h}`），資料夾分組可選 by-design / by-template / flat。

### 5.5 所有競品共同的失望：上傳焦慮

**失望點**：賣家最怕的是設計被抄。把還沒上架的圖上傳到一個不知道在哪的伺服器，
這件事本身就會讓一部分人在最後一步關掉分頁。
**我們的回應**：全程在瀏覽器內，這是技術事實不是行銷詞。而且因為是事實，我們敢把它寫在上傳區正下方。

## 6. 收入線（不進入 v1 介面，但決定 v1 的架構）

v1 不做任何付費。但架構要留好接口：

- 模板 = 一個純資料物件（`form`、`seed`、`colorways`、`printAreas`、`fieldRecipe`），
  程式生成的模板與未來「攝影模板包」共用同一個介面（都只是提供 base / field 兩張貼圖）。
  所以未來上架的模板包不需要改 shader，只需要改資料來源。
- 匯出命名規則與資料夾分組已經是可設定的，未來的 Pro 只是把預設值變成可儲存的預設集。

v1 介面**不得**出現任何未來功能的預告、waitlist、或 "coming soon"。沒做的事就不提。
