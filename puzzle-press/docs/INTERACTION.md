**這份文件在任何樣式之前完成。所有引號內的字串是要逐字出現在介面上的中文原文。**

介面語言：繁體中文（台灣用語）。`trim` / `bleed` / `gutter` / `DPI` / `KDP` 保留英文，

不是 landing page，是**單畫面工作台**。沒有 scroll-telling、沒有 feature section、沒有 pricing table、

### 0.2 閱讀順序（第一次到訪，眼睛的實際路徑）

1. 落版台中央的標題（畫面上最大的字）
2. 副標（一行，講三件被保證的事）
3. 兩個動作
4. 機台讀數（誠實的技術現況，小字但不是灰到看不見）
5. 右欄驗印單的**預估值**（此時已經有數字，這是這個 empty state 的重點）
6. 左欄備料台（已經有預設值，不是空的）

### 0.3 首屏內容清單（hero 紀律：文字元素恰好 4 個）

| # | 元素 | 內容（逐字） | 限制 |
|---|---|---|---|
| 1 | 標題 | `一份清單進去，一本可以上架的內頁 PDF 出來。` | 桌機 2 行以內 |
| 2 | 副標 | `數獨保證唯一解，迷宮保證唯一路徑，gutter 依頁數自動套 KDP 級距。` | 單行或 2 行 |
| 3 | 動作組 | 首訪：`載入範例落版單` / `貼上我的單字清單`。回訪：`沿用上次設定開印` / `換一份清單` | 一主一次，桌機不換行 |
| 4 | 機台讀數 | `引擎就緒 · 內頁字型 Atkinson Hyperlegible 尚未下載（54 KB，只下載一次）` | 單行 |

**沒有 eyebrow。沒有章節編號。沒有 scroll cue。沒有底部裝飾文字條。沒有信任 logo 牆。沒有大數字統計區。**

### 0.4 響應式

| 斷點 | 行為 |
|---|---|
| ≥ 1440px | 上表版面。落版台縮圖 `repeat(auto-fill, minmax(132px, 1fr))` |
| 1280 到 1439px | 備料台 312px，驗印單 288px。縮圖 `minmax(116px, 1fr)` |
| 1024 到 1279px | 驗印單收成落版台上方的**橫向規格條**（一列可橫向捲動的 SpecRow），完整驗印單移進一個 `<details>`。備料台 296px。縮圖 `minmax(108px, 1fr)` |
| 768 到 1023px | 單欄堆疊：備料台 → 落版台 → 驗印單。開印按鈕改為 `position: sticky; bottom: 0` 的整寬列，與狀態列合併。縮圖 `minmax(96px, 1fr)` |
| < 768px | 單欄。Masthead 的種子欄縮成只顯示碼與 ⟳，`快捷鍵 ?` 移除（觸控裝置沒有鍵盤）。備料台的四個 fieldset 變成四個 `<details>`，預設只展開 ①。落版台縮圖每列 3 張（`minmax(88px, 1fr)`）。Inspector 全螢幕接管。驗印單在落版台下方，完整顯示（它是這個產品的重點，不折疊）。 |

所有多欄版面的 `< 768px` 行為都寫在同一個 CSS 區塊裡宣告，不依賴「應該會自己 wrap」。

## 1. 核心迴圈

```
進站（首訪）
 └─ 看到：一個空的 8.5×11 版框（四角有裁切線與套印十字標）+ 4 行字
    + 右欄已經在算的驗印單（全部標「預估」）
     └─ 第一個動作：按「載入範例落版單」
         └─ 得到：8 秒內，20 題字謎 + 答案，落版台鋪滿 26 張縮圖
             → 套版動畫收攏成驗印章
             → 右欄 8 列規格從「預估」翻成「實測」，5 列驗證從「-」翻成勾
                 └─ 點任一頁進 Inspector：看到裁切線、出血框、gutter 邊界與數值
                 └─ 按「匯出內頁 PDF」：拿到一個 26 頁、字型已嵌入子集的真 PDF
                     └─ 打開來看：這是可以直接丟進 KDP 的東西

進站（回訪，第 2 本起）
 └─ 主 CTA 已經是「沿用上次設定開印」，下面寫著上次是什麼
     └─ 三次點擊開始生成：
        ① 開「我的清單庫」 ② 點一份清單 ③ 按「開印」
     └─ 若這份清單有已知的放不下問題，②之後就先擋住並提供一鍵修正
```

**為什麼下週會再打開**：因為他下週還要出書。這不是我設計出來的迴圈，是他的商業模式。
我要做的是讓第十本的設定成本趨近於零：

| 累積的資產 | 存在哪 | 在介面的哪裡看得到 |
|---|---|---|
| 上次的完整設定 | `presets` store，固定 id `last` | 首屏主 CTA 與其下方那一行 |
| 我的清單庫（含使用次數、上次用於哪本書） | `lists` store | 備料台 ② 的抽屜；每列有 `用過 3 次` |
| 每份清單「哪幾個字在哪個網格放不下」 | `lists[].tooLongWords` | 選清單當下就擋住，不必等到開印失敗 |
| 慣用開本與版面 | `presets` store（具名 preset） | 備料台 ③ 的下拉，第一項是 `上次的設定` |
| 字型與難度偏好 | 同上 | 備料台 ④ |
| 落版紀錄（最近 24 本，介面顯示 8 本） | `runs` store | 驗印單底部的 `▸ 落版紀錄 (8)` |
| 累積產能 | 由 `runs` 即時算出 | 狀態列右端 `已產出 14 本 · 1,842 題 · 驗證全數通過` |

**為什麼分享**：驗印單是可截圖的。「206 頁落在 151-300 級距，gutter 0.5 in」這種句子在 KDP 社群裡是硬通貨。

## 2. 狀態機

### 2.0 全域約定

- **Focus ring**：`outline: 2px solid var(--magenta-ink); outline-offset: 2px`。
  深色機台狀態列上改用 `var(--magenta-lift)`。全站唯一寫法，**永不移除**。
- **Active**：`transform: translateY(1px)`。不用 scale（工作台上小控制項多，scale 會讓等寬數字模糊）。
- **Disabled**：`cursor: not-allowed`，文字 `--ink-disabled`，
  **外加 4px 間距的 45° 斜線 hatch 底紋**（不靠顏色單獨傳達狀態），
  並且 `aria-describedby` 指向一段說明「為什麼不能按」。
- **Transition**：hover / active `120ms var(--ease-out)`；狀態切換 `200ms`。無過場的切換一律在下方標明。
- **所有輸入控制項的底色是 `--stock`（純白）**，坐在 `--panel` 上，
  邊框 `--rule-strong`（對白 3.47:1，符合 WCAG 1.4.11）。
  這是機台上貼的填寫欄，不是浮起來的卡片。無圓角、無陰影。
- **錯誤不用紅色**（會與洋紅衝突且不屬於這個世界）。錯誤 = **整列反白成 `--machine` 深底 + `--paper` 文字 + 上下 1px `--magenta`**，
  這是印刷廠「這一版有問題，整版標黑」的語言，比紅字更醒目且不引入第二個色相。

### 2.1 SeedField（種子欄，masthead）

格式 `XXXX-XXXX`（8 個 hex 字元，中間一個連字號）。等寬字，`--t-mono-lg`。

| 狀態 | 視覺 / 行為 |
|---|---|
| idle | 白底、1px `--rule-strong`、等寬字 `--ink`。左側有一個 8px 的洋紅套印十字圖示。 |
| hover | 邊框轉 `--ink-3`。游標 `text`。 |
| focus | focus ring。全選內容（`select()`），因為使用者 focus 進來多半是要換掉整組。 |
| 編輯中（合法） | 即時把輸入正規化為大寫 hex，自動插入連字號。右側出現 `Enter 套用` 的提示（`--t-ui-sm`、`--ink-3`）。 |
| 編輯中（不合法） | 非 hex 字元直接被吃掉（不顯示錯誤，因為使用者當下就看得到沒打上去）。長度不足 8 時 `Enter` 不生效，提示改為 `還需要 3 個字元`。 |
| 套用中 | 若已有落版成果，按 Enter 觸發 `整本重生` 確認（見 2.14）。 |
| copied | 按右側複製圖示 → 圖示 200ms 內換成勾，`aria-live="polite"` 播報 `種子已複製`。1.6 秒後換回。 |

**重擲鈕 ⟳**：自繪 SVG（兩個交錯的箭頭，印刷的「重印」記號），24px。
點擊 → 產生新種子 → 若已有成果，走 2.14 的確認流程。
快捷鍵 `R`。

**為什麼種子在 masthead 而不是備料台**：因為它不是設定，它是這一本書的**身分**。
換種子 = 換一本書，不是改一個參數。位置本身要說出這件事。

### 2.2 PuzzleTypeSelect（題型，備料台 ①）

三選一的分段控制（`role="radiogroup"`，三個 `role="radio"`）。不是下拉選單。

| 狀態 | 視覺 |
|---|---|
| idle（未選） | 白底、1px `--rule-strong`、文字 `--ink-2`。三段共用邊框，中間 1px 分隔。 |
| hover | 底色 `--paper`。 |
| focus | 整個 radiogroup 一個 focus ring；方向鍵在三段間移動。 |
| selected | 底色 `--machine`，文字 `--paper`（12.60:1）。**外加左上角一個 6px 的 `--magenta` 直角標記**（形狀 + 顏色雙重編碼）。 |
| disabled | 不存在。三種題型永遠都可選。 |

選項：`字謎`（word search）／`數獨`（sudoku）／`迷宮`（maze）。快捷鍵 `1` `2` `3`。

切換題型時：備料台 ②③④ 的內容切換（200ms 交叉淡入，內容**預設可見**，不靠 JS 救），
驗印單的預估值即時重算，落版台的成果**保留但變灰並加 hatch**，
上方出現一列：`落版台上是 100 題字謎。改用數獨要重新開印。` 附 `[清空]` 與 `[改回字謎]`。

### 2.3 CountStepper（題數）

`<input type="number">` + 減 / 加按鈕。範圍 10 到 300（上限來自 828 頁的 KDP 限制與實務）。

| 狀態 | 視覺 / 行為 |
|---|---|
| idle | 白底、等寬字置中、寬 80px。左右各一個 32px 的方形按鈕（自繪 minus / plus SVG）。 |
| hover（按鈕） | 按鈕底 `--paper`。 |
| focus | 輸入框 focus ring；上下方向鍵 ±1，Shift+上下 ±10。 |
| 超出範圍 | 值被 clamp，同時在下方以 `--ink-3` 顯示 `最少 10 題` 或 `最多 300 題（KDP 上限 828 頁）`。**不彈 modal，不清空輸入。** |
| 即時回饋 | 每次變動，下方一行 `--t-mono` 即時更新：`→ 約 106 頁 · gutter 0.375 in`。這一行是這個控制項存在的理由。 |
| disabled | 生成中。加 hatch。 |

### 2.4 WordListInput（貼上單字清單，備料台 ②，僅字謎）

`<textarea>`，`每行一個字`，高 160px（`< 768px` 時 120px）。

| 狀態 | 視覺 / 行為 |
|---|---|
| empty | placeholder（`--ink-3`，白底 6.72:1）：`每行一個字，貼上就好` + 換行 + `carrot` + 換行 + `saucepan` + 換行 + `colander`。**placeholder 不是 label**，上方有真正的 `<label>`：`貼上單字清單`。 |
| 輸入中 | 每 180ms debounce 後在下方顯示統計列（`--t-mono`、`--ink-2`）：`96 個字 · 最長 11（thermometer）· 去重後 94`。 |
| 有問題（字太長） | 統計列下方多一列**反白警示**：`13×13 放不下 2 個字：refrigerator（12）、thermometer（11）。` 附兩個按鈕：`[改用 15×15]` `[移除這 2 個字]`。 |
| 有問題（字數不足） | 反白警示：`20 個字要出 100 題，平均每個字會出現 45 次。讀者會發現。` 附 `[合併內建主題清單]`（開啟主題清單並允許多選）。門檻：字數 < 題數 × 每題用字數 ÷ 3 時觸發。 |
| 有問題（含非拉丁字元） | 反白警示：`第 7 行「蘿蔔」不是拉丁字母。字謎格線只放 A 到 Z。` 附 `[移除這 3 行]`。 |
| focus | focus ring。 |
| disabled | 生成中。 |
| 已存為清單 | 上方 label 右側出現 `已存為「Kitchen Words」· 用過 3 次`（`--t-ui-sm`、`--ink-3`）。 |

貼上後自動出現 `[存進我的清單庫]` 按鈕（hairline 樣式）。點擊 → 就地出現一個命名輸入（不是 modal），
預設值取前三個字（`Carrot, Saucepan, Colander` → `Carrot Saucepan Colander`，使用者多半會改）。
Enter 儲存，Esc 取消。

### 2.5 ListLibraryDrawer（我的清單庫）

從備料台右緣滑出的抽屜，寬 380px，`320ms var(--ease-out)`，蓋在落版台左側。
**不是 modal**（不需要保護焦點，使用者要能一邊看落版台一邊挑）。快捷鍵 `L`。Esc 關閉。

每一列（`--row-h-list: 68px`）：

```
┌──────────────────────────────────────────────────┐
│ Kitchen Words                          用過 3 次 │
│ 96 字 · 最長 11 · 上次用於《Kitchen Puzzles v2》 │
│ ⚠ 2 個字在 13×13 放不下                          │  ← 只在有紀錄時出現
└──────────────────────────────────────────────────┘
```

| 狀態 | 視覺 |
|---|---|
| empty（首訪） | 不是「暫無資料」。是一個被構成的畫面：一張畫出來的空抽屜卡（SVG，1px `--rule-strong`，四角裁切標），下方兩行：`清單庫是空的。` / `貼一份清單並按「存進我的清單庫」，或先從內建主題清單挑一份。` 加一顆 `[看內建主題清單]`。 |
| idle | 白底列，1px `--rule` 分隔。 |
| hover | 底 `--paper`，左緣出現 1px `--magenta` 直線（1px，不違反彩色 border-left 禁令）。 |
| focus | focus ring；上下方向鍵在列間移動（roving tabindex）。 |
| selected | 底 `--magenta-wash`，左緣 3px `--magenta`（此時是**選取狀態的套印記號**，不是裝飾邊框，寬度合法性以「選取指示器」論）。 |
| 有已知問題 | 第三行出現，圖示是自繪的 `slash`（斜線），不是 emoji。文字 `--ink-2`。 |
| 刪除中 | 列就地變成 `刪除「Kitchen Words」？` + `[刪除]` `[取消]`，2 秒無操作自動取消。**不用 confirm() 也不用 modal。** |

抽屜底部固定一列：`[匯入 JSON]` `[匯出清單庫 JSON]`（後者永遠可按，這是資產的逃生門）。

### 2.6 ThemeListPicker（內建主題清單）

12 組英文主題，各 48 到 60 字（實際數量以 `js/data/themes.js` 為準）。
在抽屜內以第二個分頁呈現（`我的清單` / `內建主題`）。

每一列：`Kitchen & Cooking` / `56 字 · 最長 11 · thermometer`。
最長字直接寫出來，因為它決定使用者要選多大的網格。

分頁上方一行說明（`--ink-3`）：`內建清單是英文，因為 KDP 的字謎書市場是英文市場。`
這句話必須在，不假裝是多語系產品。

支援多選（checkbox）：勾兩組 → 底部按鈕變 `[合併 2 組共 108 字]`。

### 2.7 TrimSelect（開本，備料台 ③）

不是下拉。兩張**實際比例**的小版框（8.5:11 與 6:9，高度都是 56px），
每張畫著自己的裁切角與套印十字標，下方標 `8.5 × 11 in` / `6 × 9 in`（等寬字）。

| 狀態 | 視覺 |
|---|---|
| idle | 1px `--rule-strong` 版框，內部 `--stock` 白。 |
| hover | 版框轉 `--ink-3`。 |
| selected | 版框 2px `--magenta`，四角裁切標長度由 6px 變 10px（`200ms`）。標籤字重 600。 |
| focus | focus ring 包住整組。左右方向鍵切換。 |

選 6 × 9 時，若目前網格 ≥ 17，即時降到 15 並在下方顯示：
`6 × 9 的內容區寬 5.25 in，網格上限 15 × 15。已改為 15 × 15。`

## 3. 鍵盤

### 3.1 Tab 順序

1. Masthead：`返回 hyperkit` → 種子輸入 → 複製 → 重擲 → `快捷鍵 ?`
2. 備料台：① 題型（一個 radiogroup 一站）→ 題數 → ② 清單 textarea → `我的清單庫` → ③ 開本（一組一站）→ 出血 → 大字版 → ④ 難度 → 字型（一組一站）
3. `開 印`
4. 落版台：分區標籤 → 縮圖矩陣（**整個矩陣一站**，內部用方向鍵）
5. 驗印單：`為什麼不是 100？` 的 details → `匯出內頁 PDF` → `存驗印單` → `落版紀錄` details
6. 狀態列：`取消`（存在時）

抽屜開啟時，Tab 不離開抽屜（focus trap），因為它是暫時覆蓋在落版台上的。
Inspector 不 trap（它是就地取代，不是覆蓋）。

### 3.2 快捷鍵

在 `input` / `textarea` / `[contenteditable]` 內一律不觸發。

| 鍵 | 動作 |
|---|---|
| `1` `2` `3` | 切題型 |
| `G` | 開印 / 再印一次 |
| `R` | 重擲種子 |
| `L` | 開關「我的清單庫」 |
| `E` | 匯出 PDF |
| `←` `→` | Inspector 內：上下一頁 |
| `?` | 開關快捷鍵表 |
| `Esc` | 見下 |

快捷鍵表是一個 `<details>`（就地展開在 masthead 下方的一條），**不是 modal**。

### 3.3 Esc 行為（有優先序）

1. Inspector 開啟中 → 回落版台
2. 抽屜開啟中 → 關抽屜
3. 有就地確認列（換種子 / 刪除清單）→ 取消
4. 快捷鍵表開啟中 → 關閉
5. 生成中 → **不直接取消**。第一次 Esc 顯示狀態列提示 `再按一次 Esc 取消生成`（1.5 秒有效），
   第二次 Esc 才真的取消。理由：跑到第 180 題時誤觸 Esc 會毀掉三分鐘。
6. 以上皆無 → 不做事

| 區域 | 零資料時 |
|---|---|
| 備料台 | **有完整預設值**：字謎 / 100 題 / 8.5×11 / 出血開 / 大字版開 / L3 / Atkinson。使用者按下去就知道會得到什麼，不必先做 8 個決定。 |
| 落版台 | 空版框（見 2.11.1）。四角裁切線與套印十字標已經在，這是這個世界的第一句話。 |
| 驗印單 | **已經有 8 列預估數字**。這是整個 empty state 的重點：在使用者付出任何成本之前，就看到這個工具在算 gutter 級距。 |
| 狀態列 | TallyStrip 換成一行：`還沒有落版紀錄。第一本印完之後這裡會開始累積。` |
| 我的清單庫 | 空抽屜卡 + 兩行說明 + `[看內建主題清單]`（見 2.5）。 |

**`載入範例落版單`** 是首訪的主要動作。內容：
`Kitchen & Cooking` 主題（56 字）、20 題字謎、L3、15×15、8.5×11、大字版、出血開。
20 題是刻意的：8 秒內跑完，26 頁，PDF 約 400 KB，使用者可以真的打開來看，
而且 26 頁落在 24 到 150 級距，gutter 0.375 in，剛好示範一次級距邏輯。

載入範例會**跳過清單庫寫入**（不污染使用者的資產），但**會寫入 `runs`**，
所以 TallyStrip 立刻從 0 變成 `已產出 1 本 · 20 題 · 驗證全數通過`。
第一次的累積感受在第一分鐘就發生。

## 5. 失敗路徑與復原

**本站沒有 API key、沒有雲端、沒有資料夾授權**，所以沒有那幾條路徑。
等價的外部依賴只有一個：**CDN 上的字型檔與函式庫**。它的失敗必須被當成一級公民處理。

### 5.1 Web Worker 建立失敗（`file://` 或 CSP）

**偵測**：`new Worker(url, { type: 'module' })` 包 try/catch，再加一個 800ms 的 handshake timeout。

**復原**：自動降級到主執行緒分片排程（每個 `requestAnimationFrame` 做至多 12ms 的工作就 yield）。

**文案**（狀態列上方一條，`--ink-2`，非反白，因為這不是錯誤，只是狀況）：
`Worker 無法在 file:// 下啟動，改用主執行緒分批生成。速度相同，捲動可能略頓。`

### 5.2 內頁字型下載失敗

**這條路徑不允許靜默降級。** 沒有嵌入字型的 PDF 會被 KDP 退件，而使用者不會知道。

**反白警示**（FontPicker 該列）：
`字型下載失敗（網路，或防火牆擋住 cdn.jsdelivr.net）。KDP 要求字型必須嵌入，沒有字型檔就不能產生可上架的 PDF。`

三條復原路徑，全部要做：

| 按鈕 | 行為 |
|---|---|
| `[重試]` | 同一 URL 重抓，指數退避 1s / 2s / 4s，三次後停止。 |
| `[改用備援來源]` | 切到第二個 CDN 主機（`cdn.jsdelivr.net` → `fastly.jsdelivr.net`），路徑相同。 |
| `[上傳 .ttf]` | `<input type="file" accept=".ttf,.otf">`。上傳後用 fontkit 驗證可解析並讀出 PostScript name，顯示在驗印單。這是離線環境的真正解法。 |

在字型 ready 之前，`匯出內頁 PDF` 一律 disabled，`開 印` 仍可用
（生成題目不需要字型，落版台縮圖用瀏覽器字型畫）。這個分界要講清楚：
`可以先生成題目。匯出 PDF 需要字型檔。`

### 5.3 書名或書眉含中文，但未載 CJK 字型包

**偵測**：對書名 / 書眉 / 使用說明頁做 `\p{Script=Han}` 正規表達式掃描。

**時機**：在**按下開印之前**，使用者一輸入中文書名就提示，不等到匯出才爆。

**反白警示**：
`書名含中文字。中文字型包是 Noto Sans TC（5.8 MB），只下載一次。`
`[下載中文字型包]` `[改用英文書名]`

5.8 MB 是實測值（`NotoSansTC_400Regular.ttf` = 5,766,468 bytes）。
下載時走紙條顯示真實位元組數，不是假百分比。

### 5.4 KDP 頁數邊界

| 情況 | 反白警示（逐字） | 復原 |
|---|---|---|
| 總頁數 < 24 | `目前 18 頁，KDP 平裝最少 24 頁。` | `[補到 24 頁（加 6 張空白頁）]` `[增加題數]` |
| 總頁數 > 828 | `目前 902 頁，KDP 平裝上限 828 頁。` | `[拆成兩冊（1-90 題 / 91-180 題）]` `[減少題數]` |
| 最後一頁是右頁（奇數） | 不警示。自動補一張空白頁，並在驗印單的「總頁數」列標明 `含 1 張補頁`。 |

### 5.5 字謎放不下

**時機**：貼上清單的當下就算，不等開印。

`13×13 放不下 2 個字：refrigerator（12）、thermometer（11）。`
`[改用 15×15]` `[移除這 2 個字]`

若選 `[移除這 2 個字]`：這兩個字寫進該清單的 `tooLongWords`，
記的是 `{ word, minGrid }`，所以下次選同一份清單且網格 < `minGrid` 時，選清單的當下就先擋住。

若使用者堅持不改（兩顆按鈕都不按就按開印）：那 2 個字會被跳過，
且驗印單的「版面溢出」列改成 `2 個字未放入`（反白），匯出仍允許（這是他的書，他有權決定）。

### 5.6 清單字數不足

`20 個字要出 100 題，平均每個字會出現 45 次。讀者會發現。`
`[合併內建主題清單]` `[減少題數]`

門檻：`字數 < 題數 × 每題用字數 ÷ 3`。這是提醒不是阻擋，開印按鈕仍可按。

### 5.7 難度校準未完全命中

不是錯誤，是誠實。驗印單的「難度分佈」列顯示 `L3 × 94 · L2 × 6`，
`▸ 為什麼不是 100？` 展開後三行：

```
每一題都是先產生完整解、再逐格挖空，每挖一格都用唯一性求解器確認仍是唯一解。
挖到不能再挖之後，用技巧求解器評定它實際需要的最高階技巧。
評定結果低於目標時會換一個解重來，最多 12 次；12 次仍未命中就收下較低的那一級並列在這裡。
```

**不提供「假裝全部命中」的選項。** 這一段就是這個產品在賣的東西。

### 5.8 IndexedDB 不可用（無痕模式）

**偵測**：`indexedDB.open()` 的 `onerror`，或 `navigator.storage.estimate()` 拋錯。

**降級**：`presets.last` 改存 localStorage（資料小），清單庫改為記憶體內、只在本次分頁有效。

**文案**（備料台 ② 上方一條，`--ink-2`）：
`這個瀏覽器不允許本機資料庫（無痕模式？）。清單庫這次不會被記住。`
`[匯出清單庫 JSON]`

### 5.9 IndexedDB 配額滿（`QuotaExceededError`）

`本機空間滿了。落版紀錄已自動保留最近 8 筆，較舊的 16 筆已清掉。`
`[清空落版紀錄]` `[匯出清單庫 JSON]`

清單庫**永不自動清除**（那是使用者的資產）。只清 `runs`。這個優先序要寫在文案裡。

### 5.10 生成中途取消

Esc ×2 或按 `[取消]`。Worker `terminate()`。

**已完成的題目保留**。落版台顯示：`已生成 37 / 100，其餘取消。`
並出現 `[接著生成剩下 63 題]`。因為子種子是 `hash(seed, type, index)`，
接著生成的結果與一口氣生成完全相同（位元層級一致）。介面上寫出來：
`接著生成的結果與一次跑完完全相同。`

### 5.11 PDF 封裝記憶體不足

捕捉 `RangeError` / `Array buffer allocation failed`。

`206 頁一次封裝超過這個分頁的記憶體。`
`[分兩份匯出（1-50 題 / 51-100 題）]`

分兩份時，第二份的頁碼**接續**第一份（不從 1 開始），
且兩份的 gutter 都用**合併後總頁數**算出來的級距（因為使用者最後會把兩個 PDF 合起來上傳，
或分成兩冊；介面要問一句：`兩份是要合成一本，還是拆成兩冊？`，答案影響 gutter 與頁碼）。
這個問題只有真的做過 KDP 的人會遇到，答對它就是差異化。

### 5.12 瀏覽器不支援

**偵測**：`typeof structuredClone`、`OffscreenCanvas`（可選）、`CSS.supports('clip-path', 'inset(0 100% 0 0)')`。

`需要 Chrome 90+、Edge 90+、Firefox 90+ 或 Safari 15.4+。`
空版框保留，兩顆按鈕 disabled。**不做「你的瀏覽器太舊」的整頁遮罩**（那會讓人什麼都看不到）。

### 5.13 PDF 下載被瀏覽器擋掉

`<a download>` + `URL.createObjectURL`。若 `click()` 後 1.5 秒內未偵測到下載
（無法可靠偵測，所以一律執行）：驗印單頂端保留一列常駐 60 秒的明顯連結：
`[下載 Kitchen-Puzzles-interior-8.5x11-bleed.pdf（2.4 MB）]`
60 秒後 `URL.revokeObjectURL`，該列換成 `已釋放。按「匯出內頁 PDF」重新產生。`

## 6. 招牌動效時刻：套版（Registration）

**一個被創作的時刻，不是四散的效果。** 全站只有這一段是被編排的動畫。

### 6.1 動機（一句話）

它同時完成三件事：確認每一題真的被產生了（回饋）、
把狀態從「生成中」推到「可交付」（狀態轉換）、
把注意力導向驗印單（階層）。驗印單是這個產品在賣的東西。

### 6.2 六拍（實作後修訂）

實作時多了兩拍，因為原本的四拍缺了頭尾：套印十字在生成期間沒有交代，
而第四拍的驗證列在 900px 高的視窗裡本來就在摺線以下，翻了也沒人看到。

**第零拍：停版（按下開印時，一次）**

空版框四邊中點的四個套印十字被摘下來（`.reg-fly`，`position: fixed`），
移到落版台四個邊的中點，0.52s `power3.out`，然後停在那裡直到生成結束。
版框被縮圖矩陣換掉了，機台的記號還在。
落版台的量測延到下一格畫面才做：`< 1024px` 的落版台在空版框狀態下只有一張紙那麼高。

**第一拍：上版（每完成一題觸發一次，事件驅動，不是預設 stagger）**

```js
gsap.fromTo(thumb,
  { clipPath: 'inset(0 100% 0 0)' },
  { clipPath: 'inset(0 0% 0 0)', duration: 0.24, ease: 'power2.out' }
);
```

由左往右刷過去，像滾筒經過紙面。`ease` 用 `power2.out` 不是 `power4.out`：
滾筒是機械等速的，太強的指數尾巴會讓它變成裝飾。
**縮圖的預設狀態是完全可見的**（`clip-path` 由 GSAP 從 `inset(0 100% 0 0)` 起跑，
CSS 裡沒有任何 `opacity: 0` 或 `clip-path` 初始值等 JS 來救）。

**第二拍：驗證閃動（每題驗證通過時）**

右下角的 3px 實心方塊換成 8px 套印十字（DOM 換 class，無過場），
同時 `gsap.fromTo(mark, { scale: 1.8 }, { scale: 1, duration: 0.12, ease: 'power3.out' })`。

**第三拍：套版收攏（全部完成時，一次）**

停在落版台四個邊中點的那四個套印十字飛向它們自己圍出來的中心，
`rotation: 90`、`scale: 1.7`、0.64s `power4.out`；其中三個在 0.4s 淡出。
套版就是四個記號重合成一個。

同一段 0.64s 內，落版台輕微 `blur(0) → blur(1.2px) → blur(0)`（0.32s 進、0.32s 出），
把焦點讓給中心的那個記號。
**blur 是這裡的合法動效素材**（不是裝飾，是景深）。
模糊的對象是 `#plate-body` 這個捲動視窗，**不是** `.matrix`：
258 頁的矩陣有一萬 px 高，`filter` 會逼瀏覽器把整個元素光柵化。
`< 1024px` 的落版台不裁切（捲的是整頁），那裡就不做景深。

**驗印章的圓環不在這一拍裡。** 它綁在真實完成數上（生成期畫半圈、驗證期畫另外半圈），
`strokeDasharray` + `strokeDashoffset` 從 `2πr` 走到 `0`，`ease: "none"`。
不用 DrawSVGPlugin（付費）。**圓環是量到的，不是演出來的。**

**第四拍：落章（緊接第三拍）**

活下來的那一個十字飛到驗印單的驗印章上（0.44s `power4.out`，放大到圓環直徑），
收縮 0.18s 的同時交棒給驗印章本體：圓環收口、十字 `scale 1.5 → 1`（`back.out(1.6)`，
有問題的那一本改用 `power3.out`，不過衝）、頁數 `scale 0.7 → 1` 彈進來。
這一步把「成果」與「證明」在視覺上連起來，是整段動效的論點。

**第五拍：驗印單翻牌**

先把驗證區捲進視野（0.5s `power3.inOut`，`.check-scroll` 的 `scrollTop`），
因為在 900px 高的視窗裡那幾列本來在摺線以下，而它們正是使用者付錢買的東西。
`.stamp-row` 改為 `position: sticky`，所以剛落定的驗印章不會跟著捲走。

接著每一列 `gsap.fromTo(row, { xPercent: -4 }, { xPercent: 0, duration: 0.28, ease: 'power4.out' })`，
`stagger: 0.05`，同時該列底色用 `--magenta-wash` 閃一次 200ms。
**反白的那一列不閃**：它已經是警示狀態，印刷廠不會為了一版壞掉的東西放煙火。

### 6.3 reduced motion

```js
const mm = gsap.matchMedia();
mm.add({
  reduce: '(prefers-reduced-motion: reduce)',
  ok: '(prefers-reduced-motion: no-preference)'
}, (ctx) => {
  if (ctx.conditions.reduce) return;   // 內容保持預設可見狀態
  /* 上述六拍 */
});
```

reduce 時：縮圖直接完整出現（`clip-path` 從不被設定）、
驗證標記直接是最終狀態、驗印章直接畫完、驗印單直接全部是 check。
**功能完全相同，只是沒有過場。** 沒有任何內容依賴動畫才看得見。

實作上這一整層掛在 `js/fx.js` 的一組空掛鉤上。`main.js` / `plate.js` / `dom.js` /
`drawer.js` 只呼叫 `call('...')`，從不 import `motion.js`，也從不檢查 GSAP 有沒有載到。
沒有人接手時每一次呼叫都回傳 `false`，呼叫端自己把終值寫進去。
所以 GSAP 被擋、CDN 掛掉、reduced-motion 三種情況走的是同一條路：
**少的是過場，不是資訊。**

### 6.4 不做的動效

- 沒有 ScrollTrigger（單畫面工作台，沒有 scroll-telling）。因此**只引入 `gsap.min.js`**，不引入任何 plugin。
- 沒有 hover 的位移物理、沒有磁吸按鈕、沒有游標跟隨。
- 沒有 marquee。
- 沒有「每個 section 一套進場動畫」，因為沒有 section。
- 走紙標尺、被它帶動的驗印章圓環、字型下載進度用 `ease: "none"`，因為它們綁在真實數值上。
  這是資料，不是動效。`press-btn` 的 `--progress` 同一個道理，但它留在 CSS 的
  `transition: width 100ms linear` 裡，這樣沒有動效層的時候它照樣是線性的。
- 反白警示列不做進場：警示要立刻在那裡，不是慢慢長出來。

## 7. 無障礙

- 生成進度用 `aria-live="polite"` 播報，但**節流到每 10 題一次**（每題一次會把螢幕閱讀器灌爆）：
  `已生成 60 題，共 100 題`。
- 完成時 `aria-live="assertive"`：`100 題全部生成完成，唯一解驗證 100 之 100 通過。`
- 落版台矩陣 `role="grid"`，每個縮圖 `role="gridcell"` 且 `aria-label="第 47 頁，題目 43，已驗證"`。
- 驗證標記的形狀差異（方塊 / 十字 / 斜線）讓色盲使用者可辨；`aria-label` 另有文字。
- disabled 的 hatch 底紋是視覺冗餘，語意由 `aria-disabled` + `aria-describedby` 承載。
- 所有 `<canvas>` 縮圖有 `aria-hidden="true"`，資訊由父層 `gridcell` 的 label 提供。
- Inspector 的四層標註 checkbox 有真正的 `<label>`。
- 反白警示列 `role="alert"`。

## 8. 效能預算

| 項目 | 預算 | 作法 |
|---|---|---|
| 首屏可互動 | < 1.2s | 只有 HTML + 2 個 CSS + 1 個 module。GSAP 與 pdf-lib 都 `defer` / 動態 import。 |
| pdf-lib + fontkit | **不在首屏載入** | 只在按下 `匯出內頁 PDF` 時 `await import()`（1.28 MB 合計，實測）。首訪只想看題目的人不必付這個成本。 |
| 100 題字謎生成 | < 6s | Worker，每題約 15 到 40ms。 |
| 100 題數獨生成 + 校準 | < 45s | 校準是這裡的成本（每題最多 12 次嘗試）。走紙標尺顯示真實進度。 |
| 縮圖繪製 | 每 rAF 至多 6 張 | 避免一次畫 206 張把主執行緒鎖死。 |
| PDF 排版 | 每 8 頁 yield | `await new Promise(r => setTimeout(r, 0))`。 |
| `pdfDoc.save()` | 無法分批 | 事前誠實告知。 |
| 記憶體 | 只保留題目資料結構，不保留縮圖 ImageData | 縮圖畫完就是 canvas，不另存 bitmap。 |
