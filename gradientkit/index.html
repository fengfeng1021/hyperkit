        What each export produces

        CSS

        Two blocks. The first is a plain sRGB gradient whose stops are resampled from the OKLCH curve at nine positions, so a browser without modern interpolation still gets a visually close result rather than a muddy two-stop guess. The second sits inside an @supports query and carries the real oklch() values. Both are validated with CSS.supports() in your browser before they are offered for copy, and the panel tells you which of the two it was able to check.

        SVG

        A real linearGradient or radialGradient in objectBoundingBox units, with the angle carried by gradientTransform. SVG gradients are sRGB only, so the stops are resampled to seventeen positions. A conic gradient has no SVG primitive at all, so that tab embeds a 512px raster of exactly what the Stage shows and says so, rather than silently emitting something that renders differently.

        Tailwind

        A v4 @theme block with the gradient plus three derived color tokens, and the utility usage line as a comment. No v3 config object is emitted: v3 config files are the thing v4 replaces, and shipping one would age the output on day one.

        PNG

        Rendered by the same shader at the target size, so dither and grain land at full resolution instead of being upscaled from the preview. If the device cannot allocate a 4096px surface, the export retries at 2048px and tells you it did. Vision simulation is never baked into a file.

        Versions are for gradient interpolation, written in oklch. The oklch() color function itself landed earlier in every engine. Check the current state at caniuse.com before shipping to a locked-down audience.

        Privacy

        Everything runs in this tab. No account, no upload, no analytics. Gradients you save go to this browser's local storage and nowhere else, dropped images are decoded in memory and never leave the page, and a share link carries the whole gradient inside the URL instead of on a server.
