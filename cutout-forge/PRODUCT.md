# Cutout Forge / 去背熔爐 - 產品真實

## 1. 獨特機制（一句話）

**推論跑在使用者自己的 GPU 上，所以「每多一張圖」對我們的成本是零 - 這讓「無張數上限、不上傳、不算 credit」不是行銷口號，而是架構的必然結果，而競品在結構上抄不走。**

remove.bg 每處理一張圖都要付一次 GPU 錢，所以他們**必須**計 credit。我們不付那筆錢，所以我們**不能**計 credit 也沒有理由計。這是唯一一句要打進使用者腦裡的話。

## 2. 受眾與真實使用場景

### 誰

台灣 / 東南亞 / 全球的獨立電商賣家與小型品牌的上架執行者。典型是一人或二到三人團隊，同時要顧 Shopee、Shopify、Amazon、Etsy 四個通路。不是設計師，不會開 Photoshop，但看得出邊緣有沒有毛邊。

### 在哪

- 家裡或小型辦公室的桌機 / 中階筆電（16GB RAM，內顯或入門獨顯）。Chrome 或 Edge。
- 螢幕上同時開著：這個工具、賣場後台、Excel 的 SKU 清單、一個裝滿 `IMG_4821.JPG` 的資料夾。
- 環境光通常是室內夜燈或辦公室日光燈。**暗介面在這裡不是風格選擇**：白底商品圖與棋盤格透明底必須是畫面上最亮的東西，暗底才能讓「去背成功了沒」一眼可判。

### 什麼時候

Q3 到 Q4 備貨期，或任何一次新品到貨後的隔天。攝影棚（或手機加補光燈）拍完，記憶卡裡有 80 到 300 張圖，明天要上架。**這是一個有 deadline 的重複性勞動時段，不是探索時段。**

### 什麼情緒

進站時：**疲勞 + 提防**。他已經被三個「免費試用」騙過，知道跑完 5 張就會跳付費牆。他預期這裡也一樣。
中途：**不耐 + 監視**。他不想學操作，他想看到進度條在動，而且想知道還要多久。
完成時：**如釋重負 + 想炫耀**。「我剛剛 4 分鐘處理完 200 張，一毛沒花」是他會截圖丟到賣家社團的東西。

### 一次真實的 session 長什麼樣

1. 從賣家社團的連結點進來，**帶著懷疑**，先不丟自己的檔案。
2. 按「Load 6 sample products」，想確認這東西到底能不能跑。
3. 看到 6 張在幾秒內顯影成透明底，**懷疑轉為好奇**。
4. 拖進自己那 180 張。看到模型預熱進度（44 MB，只有第一次）。
5. 切到賣場後台去做別的事，30 秒後切回來看進度。
6. 抽檢三四張，用對比分割線看邊緣。發現一張絨毛外套邊緣不乾淨，按 Retry 換高品質模式重跑那一張。
7. 選 Shopee + Shopify 兩個 preset，匯出 ZIP。
8. 看到「You have not spent $26.10」的計數器，截圖。

## 3. 這個介面必須證明的四件事

按重要性排序。做不到第一項，其他都沒有意義。

1. **證明「檔案真的沒有離開這台電腦」** - 不是靠一行文案，是靠 **拔掉網路仍然可以跑完整批**。UI 上要有可驗證的說法：模型下載完成後，狀態列顯示的網路活動歸零。這是唯一 SaaS 競品做不到的攻擊點。
2. **證明「沒有張數上限」** - 靠讓使用者一次丟 200 張，而畫面不卡、不當、不跳付費牆。第 201 張跟第 1 張的行為完全一樣。
3. **證明「這不是玩具」** - 靠 pause / resume / retry / remove 這些**只有真的在跑重活的工具才需要**的控制項，靠記憶體壓力自動降並行數，靠平台規格 preset 的細節（Amazon 主圖必須純白 255,255,255、商品要佔畫面 85%）。這些細節本身就是專業度的證據。
4. **證明「省下的錢是真的」** - 計數器的費率必須是使用者可以看見、可以改、且標明依據的。假造的省錢數字會摧毀第 1 項建立的所有信任。

## 4. 絕對不能出錯的地方

### 4.1 不能有「按了沒反應的按鈕」

這是最高優先級的禁令。模型可能載不到（CDN 被擋、企業防火牆、離線）。**每一條失敗路徑的終點都必須是一個真的能算出結果的模式**：

- 主路徑：`briaai/RMBG-1.4` via transformers.js，WebGPU（fp16）優先。
- 次路徑：同模型，WASM + quantized（44 MB）。慢很多，UI 必須誠實告知並建議分批。
- 保底路徑：**自己實作的邊緣 flood-fill chroma-key**。純 JS，零依賴，永遠可用。適用純色 / 近純色背景的商品圖，而這正是電商賣家最常見的情況（白背景棚拍）。UI 必須明說它的適用範圍與不適用範圍（不適用：絨毛、髮絲、玻璃、雜亂背景）。

保底路徑不是安慰獎，它必須被當成一個獨立的、可以主動選用的模式。有些使用者的圖全是白底，chroma-key 比模型快 50 倍且邊緣更利，他應該可以主動選它。

### 4.2 不能爆記憶體

200 張 24MP 的 JPEG 全解析度解碼 = 大約 19 GB 的 ImageData。一定當。硬性規則：

- 顯示用縮圖一律 `createImageBitmap(file, { resizeWidth: 512, resizeQuality: 'medium' })`，用完不留 File 以外的東西。
- 全解析度只在**匯出那一刻**、**一次一張**解開，寫進 canvas 出 blob 後立刻 `bitmap.close()` 並釋放。
- 推論輸入固定 1024×1024，alpha mask 以 512 邊長暫存，匯出時再雙線性放大回原尺寸疊上去。
- 並行數 = `clamp(round(hardwareConcurrency / 2), 1, 4)`，任何一次 decode 失敗或 OOM 立刻減半並在狀態列顯示原因。

### 4.3 不能弄丟使用者的工作

跑了 8 分鐘的批次不能因為誤觸就消失。硬性規則：

- 有未完成佇列時，`beforeunload` 攔截。
- Clear / Remove All 需要二次確認，且確認的按鈕文案要說明後果（`Discard 143 results`，不是 `OK`）。
- 單張 Remove 可以在 8 秒內 Undo。
- 匯出中不可被其他操作打斷。

### 4.4 不能說謊

- 費率可改、標明依據與查核日期。
- 預估剩餘時間只在跑完 5 張、有真實樣本後才顯示，之前顯示 `Measuring…`。
- 「不上傳」的說法要精確：模型權重是從 huggingface.co 下載的（一次），**你的圖片不是**。這兩件事要分開講清楚，含糊會被抓包。
- 品質不能誇大。邊緣不完美的張數要主動標記為 `Check edges`，不能全部標綠。

### 4.5 不能在第一次到訪就要求任何東西

沒有註冊、沒有 email、沒有「先看教學」。第一屏的第二個按鈕就是「Load 6 sample products」，按下去 5 秒內看到結果。

## 5. 競品在哪裡讓使用者失望

| 競品 | 具體失望點 | 我們的對應 |
|---|---|---|
| remove.bg | 免費層輸出被鎖在 0.25 MP（約 625×400），大到能用的圖一定要付錢。批次是付費功能。 | 免費層 = 全解析度 = 唯一的層。 |
| remove.bg | 訂閱制 credit 到月底歸零。旺季用不完虧，淡季不夠用又要加購。 | 沒有 credit 這個概念。 |
| Adobe Express / Canva | 要登入、要上傳、免費版有浮水印或解析度限制，且介面是為單張設計的，200 張要點 200 次。 | 零登入，拖進來就開跑，200 張一次。 |
| PhotoRoom / Pixelcut | 手機 App 為主，桌機批次體驗差；輸出規格要另外設定，不理解 Amazon 的 85% 佔比規則。 | 桌機優先的批次工作台 + 內建平台規格 preset。 |
| 所有 SaaS | **去背與平台規格輸出是兩個工具。** 賣家去完背還要再開一個 resize 工具，一張張套白底、補留白、改檔名。Amazon 退件通常不是因為沒去乾淨，是因為留白比例不對。 | 一次過關：去背 + 尺寸 + 留白比 + 白底 JPEG / 透明 PNG 雙輸出 + 自動命名 + 依平台分資料夾的 ZIP。 |
| 所有 SaaS | 上傳商品圖給第三方，對還沒發表的新品是真實的洩漏風險。沒有人明講，但賣家在意。 | 檔案不離開瀏覽器，可用開發者工具驗證。 |
| 開源 demo（Xenova / addyosmani） | 技術可行性已被證明，但它們是 demo：一次一張、沒有佇列、沒有暫停、沒有平台輸出、沒有錯誤復原。 | 我們做的正是它們缺的那 90%：**佇列管理與輸出管線**，而不是模型本身。 |

**結論：模型不是我們的護城河，工作流才是。** 去背這件事已經是 commodity，把 200 張的混亂變成一個可暫停、可抽檢、可一鍵交付的批次流程，才是使用者願意回訪的原因。

## 6. 回訪與擴散的機制

- **回訪**：每次上新品就回來一次。這是自然節奏，不需要 email 提醒。設定（preset、費率、命名規則）存在 `localStorage`，第二次回來是零設定開跑。
- **擴散**：完成畫面的「You have not spent $XX」是給賣家社團看的截圖。它必須在視覺上有份量、資訊完整（張數、費率依據），且**只在真的跑完之後才出現**。
- **站內導流**：完成後導向 `mockup-loom`（情境織機），因為透明 PNG 正是它的輸入格式。連結是相對路徑 `../mockup-loom/`。

## 7. 範圍界線（這次不做）

明確不做，避免範圍膨脹拖垮核心：

- 不做 BiRefNet（品質模式）的模型切換。單一模型 + chroma-key 保底就夠了。品質模式列為未來項。
- 不做陰影 / 倒影合成。這是 Pro 功能的想像，不是 v1 的核心迴圈。
- 不做 SKU 對應與 CSV 命名匯入。自動命名用 preset 規則 + 原檔名即可。
- 不做授權碼驗證 / 付費牆。這一站的價值就是「全部免費」，加付費牆會摧毀主張。
- 不做 IndexedDB 持久化佇列（關掉分頁後續跑）。以 `beforeunload` 攔截取代。
