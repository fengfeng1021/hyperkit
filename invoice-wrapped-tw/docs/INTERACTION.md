## 0. 兩個模式，一個資料源

| 模式 | 進入方式 | 使用者在做什麼 | 主要控制項 |
|---|---|---|---|
| **Operate（儀表板）** | 解析完成後直接落地 | 找答案：「上個月那筆兩千多的是什麼」 | 篩選、排序、展開、搜尋 |
| **Experience（年度回顧）** | 儀表板上的「產生年度回顧」按鈕 | 被講一個故事 | 只有捲動與最後的圖卡設定 |

兩個模式共用同一份記憶體內的 `dataset` 物件。回顧模式是覆蓋在儀表板之上的全螢幕檢視（`role="dialog"` + `aria-modal="true"`），Esc 或右上角「回到儀表板」關閉，關閉後捲動位置回到按下按鈕時的位置。

這是全站唯一使用「覆蓋整個畫面」的地方，理由成立：它需要保護焦點、需要接管捲動、而且是一個有始有終的線性體驗。

## 1. 核心迴圈

```
進站
  → 看到一台待命的機器：一個進紙口（drop zone），旁邊寫著它會印出什麼
  → 第一個動作（二選一）
      A. 按「載入範例資料」          ← 零摩擦路徑，預期 70% 的訪客走這條
      B. 拖入 / 選擇自己的 CSV        ← 有意圖的路徑
  → 解析（進紙動畫 + 逐列計數，真實進度）
  → 落地在儀表板：六個區塊，可以立刻開始亂點
  → 玩夠了按「產生年度回顧」→ 十屏敘事 → 最後一屏產出直式圖卡
  → 存圖 / 分享
  → 資料寫進 IndexedDB
回訪動機
  → 明年再匯入 → 自動解鎖「年度比較」章節（今年 vs 去年，同期成長率）
  → 5 月報稅季：「今年到目前為止」即時回顧
  → 分享出去的圖卡把下一個人帶進來
```

**為什麼會分享**：圖卡上的數字是使用者自己的，而且是他自己也不知道的（造訪次數、最晚的一次消費時間）。這種數字有炫耀成分也有自嘲成分，兩種都會被貼出來。

**為什麼會回來**：多年度比較是唯一無法一次消費完的功能。第一年只能看到「尚未解鎖」的說明，這個空狀態必須寫得讓人記得明年要回來。

## 2. 資訊架構與閱讀順序

### 2.1 零資料狀態（首次到訪）

首屏（一定要塞得下，`min-height: 100dvh`）：

```
┌───────────────────────────────────────────────────────────┐
│ [nav 64px]  發票回顧            ● 資料未離開此裝置   Hyperkit │
├───────────────────────────────────────────────────────────┤
│                                                            │
│  一整年的消費              ┌──────────────────────────┐    │
│  都在這捲紙上。            │                          │    │
│                            │   把 CSV 拖到這裡        │    │
│  載具明細 CSV 拖進來，     │   ┌──────────────────┐   │    │
│  離線解析，30 秒生成       │   │  選擇 CSV 檔案   │   │    │
│  年度回顧。檔案不會        │   └──────────────────┘   │    │
│  離開這台電腦。            │   支援 .csv，可一次多檔  │    │
│                            │                          │    │
│  ┌──────────────────┐      │   [ 掃描光帶 idle 動效 ] │    │
│  │  載入範例資料    │      └──────────────────────────┘    │
│  └──────────────────┘         ↑ 進紙口，齒孔邊緣           │
│                                                            │
└───────────────────────────────────────────────────────────┘
```

首屏文字元素恰好 4 個：H1、副文、主 CTA、進紙口（內含唯一的檔案按鈕）。沒有 eyebrow，沒有捲動提示，沒有裝飾字串。

第二屏以下（零資料時）：

1. **怎麼拿到你的 CSV** - 一條橫向捲動的收據紙帶，三段被撕開的紙，每段是一個真實步驟（「登入財政部電子發票整合服務平台」/「載具管理 > 消費明細下載」/「選擇年度，匯出 CSV」），每段附一個自繪的介面示意圖示與該步驟的實際按鈕名稱。不寫「步驟 1 / 2 / 3」。
2. **它會算出什麼** - 六行等寬對齊的收據列，每行左邊是指標名稱、右邊是 `- - -` 佔位。這是儀表板的預留位，資料進來後這一區直接被真實數字取代（同一個 DOM，數字用 GSAP 從佔位滾出來）。這不是假截圖，是真實元件的空狀態。
3. **這個頁面發出過幾個網路請求** - 離線證明區。即時列出 `performance.getEntriesByType('resource')` 的每一筆，標示 `GSAP CDN` / `Google Fonts` / `本地檔案`，並註明「上傳請求數：0」。附一句「你可以拔掉網路連線，重新整理，再跑一次」。
4. **Footer** - 回 Hyperkit、資料處理說明、原始碼位置。

### 2.2 有資料狀態（儀表板）

解析完成後，第 2.1 的第 1 段（教學紙帶）折疊成一行「重新匯入 / 換一個檔案」，第 2 段展開成完整儀表板。

儀表板 bento，六格，恰好六份內容，有節奏不是六個等大方塊：

| # | 區塊 | 桌機版面 | < 768px |
|---|---|---|---|
| 1 | 年度數列（總金額 / 筆數 / 店家數 / 平均單筆 / 最貴一筆 / 最常去） | 滿寬一列，六欄等寬對齊的收據列 | 兩欄 × 三列 |
| 2 | 星期 × 時段熱力圖 | 左 7 欄 | 滿寬，橫向可捲 |
| 3 | 月度金額折線 | 右 5 欄 | 滿寬 |
| 4 | 店家泡泡雲 | 滿寬，高 min(72vh, 640px) | 滿寬，高 60vh，關閉力學改用靜態網格排列 |
| 5 | 分類 → 店家 流向圖 | 左 6 欄 | 滿寬，改為可折疊的分類清單（Sankey 在窄螢幕無法閱讀，不硬塞） |
| 6 | 逐筆明細表 | 右 6 欄，虛擬捲動 | 滿寬 |

儀表板下方（非 bento）：
7. **回饋試算** - 依實際分類佔比排序的試算表，規則可編輯，附「這個數字怎麼算的」展開。
8. **產生年度回顧** - 全寬的主行動列。這是頁面上唯一的第二個主要 CTA。

## 3. 完整狀態機

以下每個物件的狀態都必須在實作中可觸發、可截圖。

### 3.1 進紙口 / Drop Zone（`#feed-slot`）

| 狀態 | 視覺 | 進入事件 | 離開事件 |
|---|---|---|---|
| **idle** | 1px `--line-2` 虛線框（`dasharray 6 4`），上下緣有齒孔（8px 半圓 repeating-radial-gradient）。內部一條 2px 的 `--vermilion` 掃描光帶以 `--t-scan` 2.4s 上下往返（`prefers-reduced-motion` 下靜止在中線且降到 `--vermilion-deep`）。 | 初始 / 任何操作結束 | 下列任一 |
| **hover** | 框改為實線 `--line-3`，掃描光帶速度加快到 1.2s，背景由 `--ink-base` 提到 `--ink-raised` | `pointerenter` | `pointerleave` |
| **focus-visible** | `outline: 2px solid --vermilion-bright; outline-offset: 3px`。掃描光帶行為同 hover。 | 鍵盤 Tab 進入內部按鈕，或 zone 本身取得焦點 | `blur` |
| **dragover** | 整個 zone 底色切到 `--vermilion` 的 12% tint，框變 2px 實線 `--vermilion`，齒孔亮起，掃描光帶停在頂端並展開成一條橫貫的接紙線。文案由「把 CSV 拖到這裡」換成「放開就開始解析」 | `dragenter` / `dragover`（`preventDefault`） | `dragleave`（需計數器抵銷子元素冒泡）/ `drop` |
| **reading** | 佔位；顯示「讀取檔案 1/3」。掃描光帶轉為單向由上往下連續掃。取消按鈕出現。 | `drop` 或 `change` | 讀檔完成或取消 |
| **parsing** | 進紙動畫：一條收據紙帶從 zone 上緣「吐」出來（`clip-path: inset()` 由 100% 到 0），紙帶上即時印出已解析的列（每 8 列印一行摘要）。旁邊等寬數字：`已讀 12,480 列 / 成功 780 / 跳過 3`。有真實百分比進度線（不是不確定進度條）。 | 讀檔完成 | 解析結束（成功或失敗）或按下取消 |
| **success** | 紙帶停止吐出，末端撕開（鋸齒 `clip-path`），整個 zone 在 420ms 內向上收摺並被儀表板取代。同時 `aria-live="polite"` 播報「解析完成，780 筆消費，涵蓋 2025 年 1 月到 12 月」。 | 解析回傳且成功列數 > 0 | 使用者按「換一個檔案」 |
| **error** | zone 維持展開，內部換成錯誤面板（見 §5）。掃描光帶停止並停在錯誤發生的那一列位置。 | 解析拋出、成功列數 = 0、或編碼偵測失敗 | 使用者按「重試」/「開啟欄位對映精靈」/「載入範例資料」 |
| **disabled** | 只在已有解析工作進行中時出現。透明度 0.45，`cursor: not-allowed`，`aria-disabled="true"`，掃描光帶停止。 | 另一個解析進行中 | 該解析結束 |
| **empty** | 等同 idle。這個元件沒有「有資料但為空」的情況。 | | |

**取消**：parsing 期間 Esc 或「取消」按鈕會 `worker.terminate()`，回到 idle 並播報「已取消解析」。

### 3.2 主 CTA「載入範例資料」（`#load-sample`）

| 狀態 | 視覺 |
|---|---|
| idle | `--vermilion` 實心填滿，文字 `--ink-void`（對比 6.08:1），radius 2px，`--shadow-panel` |
| hover | 底色 `--vermilion-bright`，`transform: translateY(-1px)`，陰影升為 `--shadow-lift`，160ms `--e-out-2` |
| focus-visible | 同 idle + `outline: 2px --vermilion-bright / offset 3px`（在 `--ink-base` 上 7.55:1） |
| active | `transform: translateY(0) scale(.985)`，陰影降回 `--shadow-row`，90ms |
| loading | 文字換成「載入範例資料中」，左側出現一個 12px 的方形印字頭，以 `--t-quick` 在 4 個位置間跳（不是圓形 spinner）。按鈕寬度**鎖定**在 idle 寬度，不得因文字變長而跳動。`aria-busy="true"` |
| success | 不停留在 success 狀態，直接進入儀表板。播報由進紙口負責。 |
| error | 範例 CSV 讀不到（極罕見，只有檔案被刪）：按鈕回 idle，下方 inline 錯誤文字「找不到範例檔案 assets/sample-invoice.csv，請確認檔案完整」 |
| disabled | 已有資料時，這顆按鈕從主 CTA 降級為儀表板頂端工具列的一個次要連結「換成範例資料」。不使用 disabled 灰化。 |

**載入範例後**：頁面頂端常駐一條 28px 高的標記帶，`--vermilion` 1px 上下線、`--ink-raised` 底、文字「目前顯示的是範例資料（2025 年，780 筆虛構消費）」+ 右側「換成我自己的檔案」連結。這條帶子在回顧模式與分享圖卡上都會出現，圖卡右下角印「範例資料」。

### 3.3 熱力圖格子（`.heat-cell`，7 × 24 = 168 個）

| 狀態 | 視覺 |
|---|---|
| idle | `--ramp-0`（無消費，等於 `--ink-raised`）到 `--ramp-6`，radius 0，格間 gap 2px |
| hover | 該格 `outline: 1px --paper`（inset），同列同行的座標軸標籤變 `--paper`，其餘標籤降到 `--paper-mute`。tooltip 跟隨，內容：`週三 21:00 / 18 筆 / NT$4,120 / 平均 NT$229` |
| focus | 格子是 `role="gridcell" tabindex="-1"`，整個熱力圖是 `role="grid" tabindex="0"`。方向鍵移動焦點，焦點格 `outline: 2px --vermilion-bright`。 |
| active / selected | 按下（Enter / Space / click）：該格 outline 變 2px `--vermilion`，下方明細表自動篩選成該時段，並在明細表上方出現可移除的篩選標籤「週三 21:00」。再按一次取消。 |
| empty | 整張圖無資料時不渲染格子，改印一行「這份資料沒有時間欄位，熱力圖需要發票日期含時間」。 |
| disabled | 不適用。 |

### 3.4 店家泡泡（canvas，非 DOM）

canvas 上以 `pointermove` 做距離命中測試（`dx*dx+dy*dy < r*r`），命中後：

| 狀態 | 視覺 |
|---|---|
| idle | 力學排列。半徑 = `sqrt(金額) × k`，最小 6px（低於 6px 的併入「其他 N 家」單一泡泡）。填色 = 分類在單一油墨階上的位置（`--ramp-1` 到 `--ramp-6`），另疊一層該分類專屬的條紋密度（0 到 5 條 / 12px），這樣色盲使用者也分得出來。 |
| hover | 命中泡泡半徑 ×1.08（120ms `power2.out`），描邊 1px `--paper`，其餘泡泡 alpha 降到 0.45。canvas 外的 DOM tooltip 顯示店名、金額、次數、佔比。游標變 `pointer`。 |
| focus | canvas 本身 `tabindex="0"`。取得焦點時進入鍵盤模式：泡泡依金額排序，左右鍵在排序上移動，被選中的泡泡外圈畫 2px `--vermilion-bright` 環，同時把店名寫進 `aria-live` 區。這是把視覺化做成鍵盤可用的最低成本做法。 |
| active | 點擊 / Enter：該泡泡脫離力學，飛到 canvas 中央（`power3.out` 520ms），其餘泡泡退到外圈（alpha 0.25），右側滑出該店家的逐筆消費列表（虛擬捲動）。再點空白處或 Esc 收回。 |
| loading | 力學前 12 個 tick 期間泡泡以 alpha 0 到 1 淡入並從中心散開（460ms），不顯示 spinner。 |
| empty | 店家數 < 2 時不啟動力學，直接畫一個置中泡泡並在旁邊說明「只有 1 家店，泡泡雲需要至少 2 家」。 |
| error | canvas 不支援（`getContext('2d')` 回 null）：整格替換成前 20 名店家的等寬排行表。功能不消失，只是換一種呈現。 |

**效能**：力學跑在 `requestAnimationFrame`，超過 300 顆時 alpha decay 從 0.0228 提高到 0.05 讓它 8 秒內收斂並停止 rAF（`isStopped` 後只在互動時重繪）。

### 3.5 流向圖節點（分類 → 店家）

| 狀態 | 視覺 |
|---|---|
| idle | 左欄分類節點（6 個），右欄前 12 名店家 + 「其他 N 家」。節點為 12px 寬的實心條，高度正比金額。連線是 SVG cubic bezier 帶狀，`fill` 用左端分類色，`fill-opacity: .35` |
| hover（節點） | 節點填色提到 `--paper`，與它相連的所有帶狀 `fill-opacity` 升到 .75、其餘降到 .08。節點旁印出金額與佔比。 |
| hover（連線） | 該條帶 `fill-opacity: .85` 並加 1px `--paper` 描邊，兩端節點同步高亮。 |
| focus | 節點是 `<g tabindex="0" role="button">`，Tab 依左欄由上到下、再右欄由上到下。focus 環：2px `--vermilion-bright`，`outline-offset: 2px`（SVG 用 `stroke` 模擬）。 |
| active（拖曳） | `pointerdown` 後節點跟隨 Y 軸移動（限制在該欄範圍內），連線即時重算。放開後同欄節點重新依新順序排列（260ms `power2.inOut`）。鍵盤替代：focus 狀態下 `Alt + ↑/↓` 上下移動一位。 |
| empty | 分類數 < 2 或店家數 < 2 時不畫，印「資料的店家分佈太集中，流向圖需要至少 2 個分類」。 |

### 3.6 明細表（虛擬捲動）

| 狀態 | 視覺 |
|---|---|
| idle | 收據列：等寬日期 / 店名（`Noto Sans TC`）/ 等寬金額右對齊 / 發票號碼等寬。列高 28px，列間無框線，每 5 列一條 `--line-1` hairline（不是每列都有線）。 |
| hover（列） | 底色提到 `--ink-raised`，左緣出現 1px `--vermilion` 標記線（1px，未超過禁令上限），日期欄變 `--paper` |
| focus（列） | 列是 `<tr tabindex="0">`，focus 環 2px `--vermilion-bright` inset |
| active（展開） | Enter / click 展開該發票的 `D` 明細列（品名 + 小計），以 220ms `--e-out` 高度展開。同一時間只展開一列。 |
| loading | 虛擬捲動載入下一批時，底部出現 3 條 28px 高、底色 `--ink-raised` 的骨架列（形狀與真實列一致，不是圓角矩形），無 shimmer 動畫。 |
| empty（有資料但篩選後為空） | 「這個篩選條件下沒有消費。」+ 一顆「清除篩選」按鈕，並列出目前生效的篩選標籤。 |
| empty（完全無資料） | 見 §4 |
| error | 不適用（資料已在記憶體）。 |

### 3.8 分享圖卡產生器

| 狀態 | 視覺 |
|---|---|
| idle | 左側 9:16 canvas 預覽（`max-height: 62vh`），右側控制：版型四選一（縮圖，非文字選單）、遮蔽金額開關、下載按鈕 |
| hover（版型縮圖） | 縮圖 `scale(1.03)`，1px `--line-3` 框 |
| focus | 版型是 `role="radiogroup"`，方向鍵切換，focus 環 2px `--vermilion-bright` |
| active（選中版型） | 2px `--vermilion` 框 + `aria-checked="true"`；canvas 在 300ms 內重繪（重繪期間舊圖保留，不閃白） |
| loading（下載中） | 按鈕文字換「產生 PNG」→「產生中」，canvas 上方蓋一條由左到右的掃描線，完成後消失。實測 < 200ms，但仍要有狀態。 |
| success | 按鈕短暫變成「已下載」1.2s 後回復。同時 `aria-live` 播報。 |
| error | 字型未載入完成就繪圖會掉字：繪圖前 `await document.fonts.ready`；若逾時 3s，改用系統字並顯示 inline 提示「自訂字型載入逾時，圖卡改用系統字型。重新整理可再試一次」。 |
| disabled | 無資料時整個區塊不存在。 |

### 3.9 離線指示燈（nav 右側，全站唯一的狀態點）

| 狀態 | 視覺 |
|---|---|

## 4. 空狀態（全部都是被構成的畫面）

### 4.1 首次到訪：整個首屏就是空狀態

空狀態不是一塊「暫無資料」的區域，而是**一台待命中的機器**。進紙口有齒孔、有掃描光帶、有明確的接受格式說明。它看起來像可以用，因為它真的可以用。

輔助元素（往下捲才會看到，不佔首屏）：
- 「它會算出什麼」的六行收據列，右側全是 `- - -` 佔位。這一區在資料進來後由同一批 DOM 節點填入真實數字，佔位到數字之間用 GSAP `snap: 1` 滾動過去。使用者因此在拿到資料**之前**就知道會得到什麼。
- 網路請求即時清單（真實資料，不是宣稱）。

### 4.2 解析成功但資料太少（< 10 筆）

不進儀表板。顯示：「讀到 6 筆消費。年度回顧需要至少 10 筆才有東西可講。」下方兩個出路：「載入範例資料看看完整版」/「再匯入一個檔案（會自動合併去重）」。已讀到的 6 筆仍以明細表列出，不浪費使用者的操作。

### 4.3 年度比較章節未解鎖（只有一年資料）

這一屏不能是「暫無資料」。設計：

畫面中央是兩捲並排的收據紙，左邊那捲印滿了今年的資料（真實摘要），右邊那捲是空白的、只印了一行「2024」與齒孔。中間一條虛線把它們連起來，虛線上寫「等一份就能比較」。

下方三個真實出路：
1. 「匯入另一個年度的 CSV」（開啟檔案選擇）
2. 「載入 2024 年範例資料」（載入 `assets/sample-invoice-2024.csv`，立刻把這一屏變成完整的比較章節）
3. 「明年提醒我」（產生一個 `.ics` 行事曆檔，事件日期為明年 1 月 5 日，內容含本站網址。純本地產生，不需要任何服務）

### 4.4 篩選後為空

見 §3.6。重點：一定要同時顯示「目前生效的篩選條件」與一顆清除按鈕。使用者最常見的困惑是不知道自己套了什麼篩選。

## 5. 失敗路徑（每一條都要有文案與復原方式）

錯誤文案格式固定為兩句：**第一句說發生什麼，第二句說怎麼辦。** 不用「哎呀」「糟糕」「發生了一些問題」。

| # | 情況 | 偵測方式 | 文案 | 復原方式 |
|---|---|---|---|---|
| 1 | **不是 CSV**（丟了 PDF / xlsx / 圖片） | 副檔名 + 前 512 bytes 檢查（PDF 頭 `%PDF`、ZIP 頭 `PK\x03\x04`） | 「這是一個 PDF 檔，不是 CSV。請到載具專區選『消費明細下載』，格式選 CSV。」 | 保留 zone 展開；提供「看下載步驟」連結捲到教學紙帶；提供「載入範例資料」 |
| 2 | **編碼判斷失敗**（雙解碼都出現大量替換字元） | UTF-8 嚴格模式解碼失敗 → 試 Big5 → 兩者的 U+FFFD 比例都 > 2% | 「這個檔的文字編碼無法自動判斷。你可以手動指定編碼，或用試算表另存成 UTF-8 的 CSV 再匯入。」 | 展開編碼選擇器（UTF-8 / UTF-8 BOM / Big5 / 手動指定），下方即時預覽前 5 列解碼結果，選對了才能繼續 |
| 3 | **欄位對不上**（找不到日期或金額欄） | 標頭比對 + `M`/`D` 前綴比對 + 型別採樣三者皆失敗 | 「認不出這份檔案的欄位。財政部改過格式時會這樣。請指定哪一欄是日期、店家、金額。」 | 開啟**欄位對映精靈**（見 §6），對映結果存 `localStorage`，同樣結構的檔案下次自動套用 |
| 4 | **有列解析失敗但整體成功** | 逐列 try / 累計 skipped | 頂端一條非阻斷提示：「780 列成功，3 列跳過。」右側「看看跳過了什麼」 | 展開列出被跳過的原始文字與跳過原因（欄位數不符 / 日期無法解析 / 金額非數字），每列附「用對映精靈修正」 |
| 5 | **金額超界或為負** | `Number.isFinite` + 絕對值 > 10^9 檢查 | 該列不丟棄，標記為異常並在明細表以 1px `--vermilion` 左標記顯示，頂端提示「3 筆金額異常（負數或超過 10 億），已列入明細但不計入統計。」 | 明細表提供「只看異常列」篩選；提供「仍然計入統計」開關 |
| 6 | **多檔重複匯入** | 依發票號碼去重 | 「合併了 3 個檔案，共 2,140 筆，其中 412 筆重複（同一張發票號碼）已略過。」 | 純資訊，非錯誤。可展開看重複清單 |
| 7 | **檔案過大**（> 40 MB） | `File.size` | 「這個檔 62 MB，比預期大很多。解析會花一點時間，也可能吃掉不少記憶體。」 | 「仍要解析」/「取消」二選一。選擇解析時強制走 Worker 分片並顯示可取消的真實進度 |
| 8 | **localStorage 寫入失敗**（配額滿 / Safari 無痕） | `try { setItem } catch (QuotaExceededError \| SecurityError)` | 「瀏覽器不讓這個頁面儲存設定（可能是無痕模式或空間已滿）。這次的分析照常運作，但欄位對映與年度資料不會被記住。」 | 全站改用記憶體內 fallback，不再嘗試寫入；提供「清除本站舊資料」按鈕（列出目前佔用大小） |
| 9 | **IndexedDB 配額滿**（多年度資料累積） | `navigator.storage.estimate()` 事前檢查 + `QuotaExceededError` | 「儲存空間不足，無法保存這個年度。目前已保存 4 個年度，佔用 38 MB。」 | 提供「只保留彙總（丟棄逐筆原始列）」的降級選項，實測可壓到原本 4%；以及逐年度刪除清單 |
| 10 | **瀏覽器不支援 Big5 解碼** | `try { new TextDecoder('big5') } catch` | 「這個瀏覽器不支援 Big5 解碼。如果你的檔案是 Big5，請先用試算表另存成 UTF-8。」 | 只在需要 Big5 時顯示；UTF-8 路徑不受影響 |
| 11 | **不支援 Web Worker / module worker** | `typeof Worker === 'undefined'` 或 module worker 建構失敗 | 不顯示錯誤。靜默降級為主執行緒分片解析（每 8ms 讓出一次），只在進度列旁註明「解析中，畫面可能略為停頓」 | 自動 |
| 12 | **Canvas 不可用** | `getContext('2d')` 回 `null`（極端隱私設定） | 「這個瀏覽器停用了 Canvas，泡泡雲與分享圖卡無法繪製。其餘功能正常。」 | 泡泡雲換成排行表；分享圖卡按鈕換成「複製文字版摘要」 |
| 13 | **GSAP CDN 載入失敗**（離線 / 被擋） | `window.gsap` 為 undefined | 不顯示錯誤。**所有內容維持預設可見**，所有互動改用 CSS transition。頁面完全可用。 | 自動。這是「內容預設可見」規則存在的理由 |
| 14 | **Google Fonts 載入失敗** | `document.fonts.ready` + `check()` | 不顯示錯誤。fallback 堆疊：`Archivo` → `Arial Narrow` → `system-ui`；`Noto Sans TC` → `"PingFang TC"` → `"Microsoft JhengHei"`；`Martian Mono` → `"SFMono-Regular"` → `Consolas` → `monospace` | 自動 |
| 15 | **解析中關閉分頁** | 不處理。 | 無 | 資料在記憶體，重進即從 IndexedDB 讀回上次成功的結果 |

## 6. 欄位對映精靈

觸發：失敗路徑 #3，或使用者主動點「欄位對映不對？手動指定」。

不是 modal（不需要保護焦點），是進紙口原地展開的面板。

版面：
- 上半：原始檔案前 8 列的等寬預覽表格，每欄頂端有一個下拉選單，選項為「日期 / 店家名稱 / 金額 / 品名 / 發票號碼 / 統一編號 / 忽略」。
- 選單旁邊即時顯示該欄的型別偵測結果（「看起來像日期：2025/03/14」/「看起來像金額：128」），這是給使用者的線索。
- 下半：即時預覽「依這個對映，會解析出這樣的 3 筆資料」。
- 底部：「套用並解析」（在日期 + 金額都被指定前為 disabled，且 disabled 旁邊寫明還缺什麼）+「記住這個格式」勾選（預設勾選，存 `localStorage`，key 為欄位標頭的 hash）。

鍵盤：Tab 依序走過每個欄位的下拉；下拉用原生 `<select>`（原生的鍵盤與行動裝置行為最好，不自造）。

## 7. 招牌動效時刻：第 3 屏「你的第二個家」

見 `docs/DESIGN-DIRECTION.md` 的逐幀規格。互動面的契約：

- 使用者的動作：從第 2 屏往下捲一格（一次滑鼠滾輪 / 一次觸控滑動 / 一次 `PageDown`）。
- 系統的回應：畫面被 pin 住 2000px 的捲動距離，在這段距離裡發生一個有始有終的事件（散開 → 聚焦 → 數字滾動 → 年輪點亮 → 收縮飛走）。
- 傳達什麼：**規模感**。「214 次」寫成文字是一個數字，畫成 214 個逐格點亮的方塊是一個體感。這是敘事型動效，理由成立。
- 使用者仍可控制：Esc 直接關閉回顧模式；`↑` 反向捲動時整段時間軸倒放（不是跳掉）；`prefers-reduced-motion` 下 pin 距離縮為 600px，數字直接顯示終值，年輪一次全部畫出。
- 年輪上任一格 hover / 鍵盤聚焦：浮出那一天的日期與金額。這是動效結束後留下的**可互動殘留物**，不是純裝飾。

### 8.3 回顧模式

### 8.4 全站快捷鍵

| 鍵 | 行為 | 備註 |
|---|---|---|
| `/` | 聚焦明細表搜尋框 | 只在儀表板可用；在輸入框內不攔截 |

### 8.5 Focus 可見性

- 全站 `:focus-visible` 使用 `outline: 2px solid var(--vermilion-bright); outline-offset: 3px`

- SVG 內元素以 `stroke` 模擬 outline，寬度 2px

## 9. 動效清單與它們的理由（每一條都必須一句話講得出來）

| 動效 | 理由（合法類別） |
|---|---|
| 進紙口掃描光帶 idle 往返 | 階層：告訴使用者這是主要互動點，而且它在待命 |
| dragover 時光帶展開成接紙線 | 回饋：確認拖曳目標已鎖定 |
| 解析中的收據吐紙 + 逐列印字 | 回饋 + 狀態轉換：把不可見的解析過程變成可見的進度 |
| 佔位 `- - -` 滾動成真實數字 | 狀態轉換：讓使用者看見「空狀態的那一格變成了這一格」，建立連續性 |
| 泡泡雲力學收斂 | 狀態轉換：資料在自行找到它的形狀 |
| 泡泡點擊飛到中央 | 回饋：確認選取，並讓後續的詳情有明確來源 |
| 回顧章節文字進場 stagger | 敘事：依序揭露，控制閱讀節奏 |
| **第 3 屏散開 / 聚焦 / 數字 / 年輪**（招牌） | 敘事：把「214」這個抽象數字轉成可數的量體 |
| 年輪收縮飛入下一屏折線圖 | 敘事：交代兩個章節之間的因果關係，不是硬切 |
| 圖卡重繪時的掃描線 | 回饋：確認版型已切換 |

**沒有的東西**：section 進場的通用淡入、hover 微彈跳、無限循環的裝飾動畫、視差背景、自訂游標。

## 11. 資料流與儲存

```
File(s)
  → ArrayBuffer
  → 編碼偵測（UTF-8 strict → Big5 → 使用者指定）
  → CSV tokenizer（RFC 4180 狀態機，處理引號內逗號與換行）
  → 列分類（M 主檔 / D 明細 / 標頭 / 未知）
  → 欄位對映（自動 → 失敗則精靈 → localStorage 快取）
  → 正規化：{ id: 發票號碼, date: Date, ts: 時間戳, store: string, taxId: string,
              amountCents: int, items: [{ name, subCents }], category: enum, source: 'sample'|'user' }
  → 依 id 去重（後匯入的覆蓋先前的，因為使用者通常是在補資料）
  → 彙總：byMonth / byWeekdayHour / byStore / byCategory / extremes
  → 記憶體 dataset（唯一真相）
       ├→ Operate 檢視（儀表板）
       ├→ Experience 檢視（回顧章節）
       └→ IndexedDB（`invoice-wrapped` DB，`years` store，key = 年份）
```

**金額一律以「分」為單位的整數計算**，只在輸出時除以 100。避免浮點誤差在七百筆累加後跑出 `NT$248,309.99999`。

**分類規則**：`assets/category-rules.json`，以店名關鍵字比對（`7-ELEVEN|統一超商` → 超商）。規則檔在 UI 上可檢視，未命中的店家歸「其他」並在儀表板上提供「把這家店歸到...」的手動分類（存 localStorage）。這比藏一份黑箱分類表誠實。

**localStorage keys**（全部以 `iwtw:` 前綴）：
- `iwtw:colmap:<headerHash>` 欄位對映
- `iwtw:cat:<storeName>` 手動分類
- `iwtw:cardrates` 使用者編輯過的回饋費率
- `iwtw:seen` 是否看過教學

**IndexedDB**：`iwtw` / `years`（key: `2025`，value: `{ summary, invoices?, savedAt }`）。`invoices` 在配額吃緊時被丟棄，只留 `summary`。
